# AVC — design qualification and delivery roadmap

**Revised 2026-10-28.** [Design](design.md) is the selected v0 architecture; [research](research.md) records evidence and rejected choices. The format is *not yet published/stable* and the current Rust 0.0.1 code remains an unrelated Git-command prototype.

Qualify the selected native semantics rather than restarting a general VCS search. Product invariants and implementation choices have different status: correct demonstrated failures and evaluate consequential representation costs before format freeze. Git interoperability is a deferred boundary interface, not a required Git backend; conversion, a synchronized bridge and a protocol-facing adapter remain alternatives to qualify. No native engine is implemented by this plan.

## Milestone 0 — independently verify the selected contracts

**Current finite evidence (2026-10-27):** Python and independent Node encoders/decoders agree on **25 pinned vectors across seven kinds / 42 typed objects**. The codec suite has **22 tests**, including 32 seeded cross-language radix maps, re-hashed mutations, binary/nested conflicts, typed provenance/result binding, retired-tag rejection and private-amend/source-export closure separation. The privacy regression failed under the prior owning-audit contract and now passes in both runtimes. Separate references exercise exact sparse LCS and bounded all-optimal confluence (961 exhaustive alignment pairs and 3,375 three-way cases), source semantics, root/GC/CAS interleavings and real SQLite transaction/backup boundaries. The new map study compares logical layout costs, not engine performance. Earlier width-group/candidate fixtures are deliberately retired; unreleased Conflict/Provenance bytes and dependent IDs are explicitly repinned. Clean-source IDs are unchanged. **No native engine, full merge proof or power-loss qualification exists.**

The [authoritative design](design.md) owns source authority, typed objects, candidate codec/layout, binary conflicts, workspace/recovery and commit/GC ordering. Before permanently writing native user data, qualify these contracts with **independent** decoders/models and golden vectors:

1. **Canonical typed object encoding (Python/Node vectors agree; native Rust verification outstanding):** independently reproduce BLAKE3 framing, **typed external ID**, kinds 1–7, exact 4096-byte leaf-size inequality, nibble prefix compression and parent-context parity, fixed-width lengths, path bounds and canonical map reconstruction. Publish and cross-check byte+hash vectors for empty map/source, files, symlinks, prefix-name pairs, threshold branches, odd-nibble boundary, directory moves, binary/nested root conflicts and Revision/typed Provenance; reject hash mismatches, missing closure, bad padding, invalid root types and noncanonical alternate trees. Two independent decoders/builders must agree before the first **durable native repository** is created.
2. **Pure source model:** independently check Put/Remove/CopySubtree/MoveSubtree as a conditional two-phase structural+leaf transaction, including exact old/absent witnesses, overlapping/swap rejection, relocated **descendant path-bound proofs** and retention of referenced copy sources. Random edit order yielding the same logical tree must produce the same StateId. Test huge directories, ancestor/descendant keys and all 4095/4096/4097 leaf boundaries.
3. **Conflict source algebra:** independently exercise equality/base rules, **sparse match-pair LCS with bounded all-optimal confluence** and content-derived budgets (not whole-file cell counts), transient execution failure without an output State, exact hunk boundaries, CRLF/duplicate-lines and text/binary/mode/type cases; verified user-recorded moves versus heuristic lookalikes, **new additions under renamed directories**, and deletion/rename coupled subtree/root conflicts. Confirm opaque binary nesting, grouping-sensitive source equality and no inner cancellation, **recursively present directory alternatives in a State-root conflict**, and that **nesting >64/graph-budget overflow refuses** a new State with protected input roots. Model criss-cross frontier reduction with virtual ancestry, already-conflicted inputs and absent/non-directory descendants; read unaffected siblings without wrongly assuming a missing sparse object is absence. Marker round-trip cannot resolve conflicts implicitly.
4. **Revision evolution:** divergent amendments, single-parent rebase, split/fold explicit lineage, and generational operation undo versus exact **inverse-content revert/reapply** formulas, including multi-parent mainline selection. Verify separate Revision/State/ChangeIds, canonical revision/provenance acyclicity and the separately owned evolution graph, including expired endpoints; reject unrequested descendant rewrites and undefined merge-commit rebases.
5. **Workspace and capture state machine:** separate selection/capture/materialization generations, acknowledgement and retention pins, observation coverage, watcher gaps and honest writer-quiesced labels. Check capture promotion against its exact recorded parent (never an equal-State lookup), explicit partial coverage, fresh ChangeId/idempotent retries and preserved observation provenance. Test unknown untracked obstacles, symlink containment, dirty/clean races, journal and marker-manifest durability before the first mutation, unchanged/edited/missing-manifest marker capture without implicit resolution, guarded inode/path replay, verification timestamps and `Incomplete` recovery after process kill. Distinguish strong **fresh-directory** no-clobber restore from inherently racy **in-place** switches. Qualify private return points with exact history bases and inclusion dispositions: parked protection must survive ordinary capture expiry, failed/stale resume and workspace closure, then hand off durably only after verified completion. Previous-switch navigation changes only on completion, not on partial writes; resuming must not transplant WIP or invent ancestry.
6. **Object durability and GC (bounded models/probes landed):** [Finite-state tests](experiments/authority_model.py) enumerate one-object reader/stage/root/export/GC interleavings, expose deletion after stale marks and protect current pins. [Real SQLite probes](experiments/test_sqlite_custody.py) exercise WAL/FULL, segmented payloads beyond a lowered row limit, atomic root/receipt/outbox rollback and a self-contained online backup. These are single-object toy closures, not a store, process-crash or power-loss qualification. Next qualify complete multi-object closure, staging/retirement and bounded cleanup, short transaction/lease boundaries, protection-epoch GC restarts/starvation, disk-full/checkpoint behavior, receipt retries and independent export/restore on supported filesystems.
7. **Typed-operation and cost qualification before format freeze:** the closed Transform/Merge/Observation wire shapes now exist in the design and both reference codecs; independently verify their execution/admission contracts, exact base/side/result bindings, non-owning audit commitments versus separately protected evidence inputs, observation coverage/resolution choices and replay refusal when evidence expires. Frontier/virtual traces are derived from fixed inputs/algorithms, not another stored log. Unknown algorithms cannot authorize execution. The [layout study](experiments/map_layout_study.py) compares flat/packed/one-key radix logical bytes and object counts; add representative lookup/diff/move and reference working-memory evidence without claiming engine throughput. The [controlled source study](experiments/text_merge_study.py) has eight disjoint-edit cases: the preceding unique-only policy conflicts on four harmless blank-line edits; the refined candidate, Git and Jujutsu all produce the intended bytes in all eight. These are synthetic edits on pinned real source, not sampled merge histories or a performance/usability result. Measure remaining ambiguity and budget fallback on real histories. Qualify binary depth budgets on wide composition chains. Revise failed candidates before stable data, not at Milestone 5.

8. **Workflow/privacy qualification:** use the selected [UX contract](ux.md) for first authoring without a synthetic commit; new/ignored/deleted-path consent; immutable partial-commit previews; editor/selection changes during review; excluded-work expiry; scoped history undo versus file recovery; divergent change-reference resolution; coupled conflict confirmation; and interrupted switch/recovery. Verify that source exports omit discarded non-parent audit inputs while explicit private evidence exports disclose their scope. The transcripts are paper contracts, not a tested CLI. Before enabling each workflow, exercise its actual entry point against well-configured Git and Jujutsu in ordinary single-directory and optional multi-workspace workflows, including unnecessary conflicts, responsiveness, environment setup/navigation/cleanup and wrong-server test risks. Do not manufacture permanent tests of mock command output before an implementation exists.

**Milestone-0 exit gate (currently NOT met):** at least two independent object codecs agree on published golden vectors; a separate pure reference model exercises the corrected structural/merge/recovery invariants; and modelled local GC/pin and workspace interleavings have no unresolved loss/cycle/ABA counterexample. Typed operation/admission semantics and representative pre-freeze layout/merge evidence must also be reviewed. Native exchange security and hosted evidence/candidate identity are their own Milestone-3/4 pre-ship gates, not prerequisites for initial local custody. Record failed cases explicitly. Correct unreleased constants and fixtures explicitly **before any persistent native data** is entrusted to them; published formats require a new identity and migration. Model checking of the concurrent state machines is a release qualification, not proof from reading this document.

## Milestone 1 — native local source custody

Build a cohesive native library/CLI from the qualified specification; the legacy Git-wrapper code, its interfaces and tests are **disposable**, with no migration or backwards-compatibility commitment. Never silently interpret a Git/prototype repository as a native one. Build the typed content objects and deterministic radix source tree, StateId, RevisionId, logical ChangeId/evolution, SQLite-only local authority with bounded segmented object staging, typed provenance and independent native export/backup. No hosted candidate objects or external large-object backend are required.

A complete local user should be able to initialize, inspect status, record a revision, list/history/diff/show exact source by ID, move/copy a subtree, reopen the repository, create a separate workspace, **preserve and resume serial work in-place with its exact history base, protected before-images and honest limitations**, and restore safely to a newly allocated directory **without Git, network or daemon**.

**Hard gates:** every acknowledged root has complete durable object closure; wrong hashes reject; no path escape or silent name collisions; equal source content produces equal canonical StateId; a no-op content write or timestamp-only observation cannot alter StateId (status/capture coverage may still change); init pins an unauthored empty State and the first commit has no parent; source export does not hydrate private audit commitments; incomplete filesystem observations are labeled honestly; recover after injected process crashes and disk-full conditions. Native verified export/backup supports independent source custody. Run actual Rust tests/lint/toolchain checks once Rust code changes.

## Milestone 2 — recoverable work and history composition

Implement distinct capture/head/selection generations, expiring recovery and explicitly pinned parked-work retention. Work through typed conflicts, symbolic markers with round-trip manifest, conservative content merging, rebase/amend evolution, source revert, operation undo and explicit reapply.

Cases: competing agents (choose one), compositional independent agents (combine selected changes), same-path edits, directory move/edit, delete-vs-modify, binary conflicts, already conflicted source, criss-cross multiple bases, concurrent workspace status/capture, crash between root selection and directory creation.

**Hard gates:** nested binary representation never drops/cancels an original input; an over-budget merge fails **without** an invented output State but keeps explicitly pinned inputs. No permanently clean uncontrolled files; no acknowledged capture missing bytes within retention. In-place switching requires explicit preservation policy for dirt/obstructions, refuses unknown coverage, preserves before-images and does not overwrite post-crash external edits. Parked work survives ordinary checkpoint expiry and interrupted resume; pin release requires verified materialization plus durable recovery handoff. Exercise A → B → return to A, exact original ancestry, inclusion dispositions and registration closure without source loss. Conflicting proposals remain recoverable; separate workspaces incur no shared logical head contention. Tests run against **immutable built source**, not mutable worker files. Qualify the UX contract's exact selected-candidate promotion/amendment, prepared-checkpoint retention, history-only undo diagnostics and whole-unit coupled resolution rather than exposing backend state-machine terms to users.

## Milestone 3 — native source protocol and ephemeral handoff

Expose the same typed semantics in a library and native protocol: get file/range/tree by source ID, diff, history/ancestry, conditional source transform, merge, draft sync and protected target update. Implement resumable batched transfer plus sparse object hydration; full copied repositories must operate offline.

**Protocol pre-ship gate:** negotiate bounded/versioned transfer, complete-root sparse witnesses and explicit missing/promised status; qualify authorization changes, cross-tenant existence tests, path-restricted filtered responses and server-side conditional transforms. Local conditional generations, receipt retry and outbox mechanisms are qualified in the earlier local milestones, independently of hosting.

Critical end-to-end test: full client chooses a revision; an isolated container/microVM receives the needed immutable source (without a full history clone), edits ordinary files, submits a **durably pinned immutable authored revision** and terminates; a second machine reconstructs exactly the submitted source. Repeat under network failure, retries, missing partial objects, restart, authorization revocation and GC.

**Hard gates:** an unpinned upload is never reported as durable handoff; source read permission is checked on rooted closure and path scope; no raw sibling proof disclosure beyond policy; guessed hashes do not bypass authorization; no client interprets promised-but-absent as source absence; unknown submit responses are resolved through durable idempotency receipts.

## Milestone 4 — shared integration and candidate validation

Specify a separate versioned hosted candidate identity/evidence wire format (not retired local kind 9), then implement typed candidate inputs, validation attestations, shared target policy and compare-and-swap, batching selected work, accepted/verified options and durable publication receipts. Integrate native source-state equality with external test/build provenance without incorporating CI into the VCS engine.

**Hard gates:** independently reproduce exact candidate identity and authenticated evidence framing/trust; verify manual Transform replay, policy/toolchain/source freshness and complete target-owned custody. The abstract authority model covers CAS/receipt ABA only, not these hosted guarantees. Signed tests apply to exact candidate, declared environment/toolchain and trusted policy; stale target/policy/auth inputs invalidate acceptance; protected ancestry rules are checked; concurrent proposals remain preserved. A linear target serializes **only its own** acceptance, with monotonically increasing generation and persisted receipt/outbox. Retries after unknown responses are idempotent and duplicate side effects are rejected.

## Milestone 5 — performance and platform qualification

Build on Milestone 0's pre-freeze reference cost evidence with actual engine/platform measurements. Tune physical segment sizing, compression/chunking, derived indexes and transport without changing canonical IDs. If canonical layout changes are justified after release, use explicit format migration; no silent retuning of hash inputs.

| Benchmark | End-to-end measures |
| --- | --- |
| Human edit-test-repeat, tiny and medium repos | status, revision write, diff, first read, memory and source recovery |
| Serial interruption/return versus concurrent directories | exact resumed work/base, errors, setup/navigation/cleanup, dependency/cache cost and process/server affinity |
| Private agent saves, millions of bounded captures | durable admission rate, quota behavior, retention reclamation |
| 1/8/32 independent writers | throughput, time spent in physical write transactions, false logical conflicts |
| 100k revisions, large trees and wide directories | cold/hot path lookup, diff, subtree moves, canonical node counts, GC |
| Path-Merkle vs inode-indirected **reference study** (only if material costs emerge) | identical source edits at shallow/deep paths and large inode counts: bytes rewritten, object/node counts, read/diff/rename costs, index maintenance and history-independent StateId validation; no unmeasured canonical-model switch |
| Physical-store profiles under **equal acknowledged durability** | baseline SQLite-only segmented custody vs a future external backend only if measurements justify one, plus optional CDC/deltas: WAL/FULL sync, p50/p95/p99 admission, reader/checkpoint/GC/backup, cold hydration, bytes per capture and authored revision, delta read amplification |
| CI and remote microVMs | cold source acquisition, sparse API calls, transfer bytes, shared-cache effects |
| Real merges and refactoring histories | wrong auto-merge rate, unnecessary conflict rate, latency and review burden |
| Process kill/power loss/disk full/remote outage | acknowledged source survival, staging/GC races, backup restore, recovery time |

Use comparable durability, source content and wall-clock total workflow against tuned Git/Jujutsu and relevant existing alternatives. Report software versions, machine/filesystem, raw measurements, cache warmth, retries and failures; do not present Scion/Enroute's fleet figures as AVC speedups.

**Platform qualification:** Linux filesystems, APFS and Windows have different rename/fsync/symlink/name rules. Test the supported feature subset explicitly. Treat a successful process-kill experiment as *insufficient* proof of power-loss safety. If an **optional managed/FUSE workspace** is later developed, separately test buffered/mmap writes, open-handle and inode/cache invalidation across root switches, true fsync/fdatasync/fsyncdir behavior, uncertain unmount, crash recovery and time-to-durable-capture receipts. It must not become a prerequisite for ordinary workspaces.

## Deferred independent questions

Engineering qualification and discretionary integrations remain: published **independent codec vectors and parser limits are mandatory Milestone-0 gates**, not optional physical optimizations. LayerFS comparisons are **later physical/workspace qualification**, not new Milestone-0 blockers or evidence for replacing AVC's canonical State representation. Physical blob/chunk compression, future source-metadata expansion, hosted cache layout and a Git interoperability interface (conversion, synchronized bridge or protocol-facing adapter) and an optional Fossil-like `avc web` viewer over the native APIs are deferred interfaces. Git interoperability must report unsupported/lossy cases and preserve native export as the full-fidelity custody path; it is not a promise of native Git-compatible IDs or lossless arbitrary-history round trips. The **4096-byte canonical map leaf rule and nibble partition** are defined rules of the current candidate codec, not runtime tuning knobs. They remain subject to the pre-freeze evidence gate; after release, changing them changes format identity. Keep the project named AVC; do not add a required Git-compatible mode, hosted forge, process sandbox, or custom consensus layer.

**Release rule:** trust source integrity, explicit undo/merge behavior, capture/restore honesty and independent export/backup before encouraging users to entrust irreplaceable code. No native implementation or verified production speedup is implied by this design package.
