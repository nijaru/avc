# AVC — design qualification and delivery roadmap

**Revised 2026-10-29.** [Design](design.md) is the selected v0 architecture; [research](research.md) records evidence and rejected choices. The format is *not yet published/stable* and the current Rust 0.0.1 code remains an unrelated Git-command prototype.

Qualify the selected native semantics rather than restarting a general VCS search. Product invariants, architecture and proposed interactions have different status: correct demonstrated failures and evaluate consequential representation costs before format freeze. Do not call the UX selected merely because the backend can implement it. Paper-qualify basic work addressing and recovery/authoring distinctions before fixing the everyday CLI; test complete entry points before enabling each feature. Git interoperability is a deferred boundary interface, not a required Git backend; conversion, a synchronized bridge and a protocol-facing adapter remain alternatives to qualify. No native engine is implemented by this plan.

## Milestone 0 — independently verify the selected contracts

**Current finite evidence (2026-10-29):** Python, Node and an isolated [Rust codec fixture](experiments/codec_rust/main.rs) agree on **25 pinned vectors across seven kinds / 42 typed objects**. Rust constructs the examples from typed values and uses a separate hash backend, not Python/Node code. The **22-test codec suite** includes 32 seeded cross-language radix maps, 200 deterministic re-hashed mutation cases, binary/nested conflicts, typed provenance/result binding, retired-tag rejection and private-amend/source-export closure separation. Explicit corpus addresses preserve corrupt-at-address cases rather than silently rehashing them. Rust's four unit checks and the shared corpus pass in debug and release; [details and limits](research.md#18-rust-codec-qualification--october-29-2026) remain distinct from native engine qualification.

Separate references exercise exact sparse LCS and bounded all-optimal confluence (961 exhaustive alignment pairs and 3,375 three-way cases), source semantics, root/GC/CAS interleavings and real SQLite transaction/backup boundaries. The [public-input studies](research.md#20-public-history-and-map-access-costs--october-29-2026) add cold lookup/Merkle-diff/relocation costs and Python allocation evidence on a pinned Git snapshot plus controlled trees, not engine performance. On the same 64 actual same-path triples from 14 merges, the [sparse ambiguity refinement](research.md#21-sparse-ambiguity-without-a-dense-fallback--october-29-2026) improves the draft from 40 to 54 clean results versus Git/Jujutsu's 58, preserving every prior clean output. The same single allocation probe falls from about 310 to 17 MiB. The matrix gate is retired because no matrix is allocated; other limits are unchanged. All clean outputs match historical bytes, which are comparison references, not correctness oracles. These are finite, biased samples, not accuracy or usability rates.

The independent [work-lifecycle model](experiments/work_lifecycle_model.py) adds six tests, including 15,120 ordered single-resume schedules, return at Revision/initial bases, capture attribution, reservation/receipt guards and sequential registration closure; it abstracts admitted source closure and transactions, not filesystem recovery or the full workspace state machine.

Ten [selected-authoring tests](experiments/test_selective_authoring.py) exercise first-commit subsets, recorded-base/origin recovery, private Observation projection, constructed-hunk replay, pinned previews and cancellation/stale-selection guards using actual canonical objects; selected exports also pass independent Node and Rust verification. This is a regular-file, in-memory authority reference, not a scanner, native store or complete admission implementation.

Fourteen [typed-operation tests](experiments/test_operations.py) now replay actual canonical records, including two-phase transforms, Source Merge, recursive criss-cross/three-base history, protected evidence expiry and required observation/conflict-choice checks. The [reference and limits](research.md#19-typed-operation-and-evidence-qualification--october-29-2026) distinguish those checks from native admission: move-evidence replay is covered, and observation facts come from a trusted fixture boundary rather than a scanner.

Fourteen [recorded-move tests](experiments/test_move_merges.py) now qualify bounded Source Merge transport, matching mappings, original-scope collisions, witnessed populated-destination overwrites and explicit old-name recreation. They preserve left/right symmetry, private-intermediate protection, opaque ancestors and no-State failure at depth/path bounds. Review exposed an ordered Directory-Put overflow that a later removal could hide; replay now validates every ordered view, and the regression fails on the pre-fix implementation. [Source scope and draft clarifications](research.md#23-recorded-move-source-merge-qualification--october-29-2026) distinguish those cases from native admission.

Nine further [history-move cases](experiments/test_move_merges.py) bind evidence to the exact recursively computed base, including new Conflict/Blob objects absent from the input store. Derived protection adds only that computed owning closure, not unpinned private audit inputs or unused grants. Virtual-base reductions remain source-only, with evidence-specific results excluded from their cache. [History scope and limits](research.md#24-history-moves-and-derived-base-protection--october-29-2026) preserve unrelated-base permission, resource refusal and the distinction from native leases/admission; the added multi-Move case preserves an opaque conflict moved as a whole unit.

Eight [composition tests](experiments/test_move_composition.py) now cover independent and partially shared batches, 64 three-unit mapping-ownership pairs in both side orders, closed original-value conflict scopes, safe outside composition and pair/closure planning-budget refusal. The [qualification and limits](research.md#25-multiple-mappings-and-closed-conflict-scopes--october-29-2026) include scope growth and additional unresolved siblings, not a demonstrated minimum burden or native cost.

Eight [agreed-query tests](experiments/test_source_queries.py) now exercise shared descendants under nested coupled conflicts, typed equality, absence versus obstruction, exact opaque endpoints, path bounds and read-only protection. The [reference and limits](research.md#22-agreed-descendant-query-qualification--october-29-2026) cover complete protected inputs, not sparse promises/hydration or native leases. Missing acquisition refuses as unknown; an agreed read cannot authorize an edit through a conflict.

Earlier width-group/candidate fixtures are deliberately retired; unreleased Conflict/Provenance bytes and dependent IDs are explicitly repinned. Clean-source IDs are unchanged. **No native engine, full merge proof or power-loss qualification exists.**

The [authoritative design](design.md) owns source authority, typed objects, candidate codec/layout, binary conflicts, workspace/recovery and commit/GC ordering. Before permanently writing native user data, qualify these contracts with **independent** decoders/models and golden vectors:

1. **Canonical typed object encoding (bounded Python/Node/Rust fixtures agree):** independently reproduce BLAKE3 framing, **typed external ID**, kinds 1–7, exact 4096-byte leaf-size inequality, nibble prefix compression and parent-context parity, fixed-width lengths, path bounds and canonical map reconstruction. Publish and cross-check byte+hash vectors for empty map/source, files, symlinks, prefix-name pairs, threshold branches, odd-nibble boundary, directory moves, binary/nested root conflicts and Revision/typed Provenance; reject hash mismatches, missing closure, bad padding, invalid root types and noncanonical alternate trees. Two independent decoders/builders must agree before the first **durable native repository** is created.
2. **Pure source model:** independently check Put/Remove/CopySubtree/MoveSubtree as a conditional two-phase structural+leaf transaction, including exact old/absent witnesses, overlapping/swap rejection, relocated **descendant path-bound proofs** and retention of referenced copy sources. Random edit order yielding the same logical tree must produce the same StateId. Test huge directories, ancestor/descendant keys and all 4095/4096/4097 leaf boundaries.
3. **Conflict source algebra:** independently exercise equality/base rules, **sparse match-pair LCS with bounded all-optimal confluence** and explicit content-derived rank/enumeration/combination budgets, transient execution failure without an output State, exact hunk boundaries, CRLF/duplicate-lines and text/binary/mode/type cases; verified user-recorded moves versus heuristic lookalikes, **new additions under renamed directories**, and deletion/rename coupled subtree/root conflicts. Confirm opaque binary nesting, grouping-sensitive source equality and no inner cancellation, **recursively present directory alternatives in a State-root conflict**, and that **nesting >64/graph-budget overflow refuses** a new State with protected input roots. Model criss-cross frontier reduction with virtual ancestry, already-conflicted inputs and absent/non-directory descendants; read unaffected siblings without wrongly assuming a missing sparse object is absence. The bounded agreed-query reference now covers complete protected States; sparse per-branch unknowns and native read/protection lifecycles remain unqualified. Marker round-trip cannot resolve conflicts implicitly.
4. **Revision evolution:** divergent amendments, single-parent rebase, split/fold explicit lineage, and generational operation undo versus exact **inverse-content revert/reapply** formulas, including multi-parent mainline selection. Verify separate Revision/State/ChangeIds, canonical revision/provenance acyclicity and the separately owned evolution graph, including expired endpoints; reject unrequested descendant rewrites and undefined merge-commit rebases.
5. **Workspace and capture state machine:** separate selection/capture/materialization generations, acknowledgement and retention pins, observation coverage, watcher gaps and honest writer-quiesced labels. Check capture promotion against its exact recorded parent (never an equal-State lookup), explicit partial coverage, fresh ChangeId/idempotent retries and preserved observation provenance. Test exclusion of live control DB/WAL/staging/journal files from broad discovery, refusal of explicit administration capture and materialization collisions/aliases without globally banning canonical names, unknown untracked obstacles, symlink containment, dirty/clean races, journal and marker-manifest durability before the first mutation, unchanged/edited/missing-manifest marker capture without implicit resolution, guarded inode/path replay, verification timestamps and `Incomplete` recovery after process kill. Distinguish strong **fresh-directory** no-clobber restore from inherently racy **in-place** switches. Qualify private return points with exact history bases and observed path origins: protection must survive ordinary capture expiry, failed/stale resume and workspace closure, then hand off durably only after verified completion. Distinguish two unfinished efforts at one base before first authoring; local reference bindings must follow the sole active Selection and scope-matching recovery observations, or an exact inactive descriptor, without a competing source head. Late captures from another effort and equal-base history undo must not cross work scope; qualify repository-level discovery and clean-reference closure. Previous-switch navigation changes only on completion, not partial writes. The bounded lifecycle and selected-authoring references exercise parts of that authority contract; full preview/capture, scanner coverage/quota, independent materialization journals and real filesystem paths remain unqualified. Active presentation records must own required conflict/pending inputs independently of ordinary checkpoint expiry. New files captured for recovery stay untracked on resume/fresh recovery; old capture origins never act as authoring consent. Authoring a subset uses a separately confirmed candidate with public Observation scope narrowed to that selection, not the private inventory. Resuming must not transplant WIP or invent ancestry.
6. **Object durability and GC (bounded models/probes landed):** The [six-object custody model](experiments/closure_custody_model.py) and [tests](experiments/authority_model.py) enumerate shared-descendant stage/root/reader/export/GC interleavings, exact-root leases and versioned renewal/expiry. They expose root-only marking, unversioned staging and protection-epoch ABA; changed epochs restart GC. [Real SQLite probes](experiments/test_sqlite_custody.py) add generation guards, logical retirement, bounded segment cleanup, header-last deletion and key-reuse exclusion to the existing WAL/FULL staging, atomic receipt/outbox and online-backup cases. [Qualification and limits](research.md#26-multi-object-custody-and-gc-qualification--october-29-2026): known immutable toy manifests, not a native store, process-crash or power-loss proof. Next qualify native typed closure discovery/protection, large-manifest transaction/lease bounds, sustained churn/starvation, disk-full/checkpoint behavior, receipt retries and independent selected export/restore on supported filesystems.
7. **Typed-operation and cost qualification before format freeze:** the closed Transform/Merge/Observation wire shapes now exist in the design and all three reference codecs; the bounded [operation reference](experiments/operation_reference.py) checks exact base/side/result bindings, separately authorized/protected inputs, evidence expiry, virtual ancestry and required observation/resolution obligations. The bounded Source/History Merge reference now covers old-directory additions, multiple-mapping composition, closed coupled scopes and exact computed-base evidence without silently following inferred intent. Complete independent execution/admission qualification still needs broader workloads, real observing authority and the native protection/admission lifecycle. Frontier/virtual traces are derived from fixed inputs/algorithms, not another stored log. Unknown algorithms cannot authorize execution. The [access study](experiments/map_access_study.py) extends the [layout comparison](experiments/map_layout_study.py) with pinned snapshot lookup/diff/move costs and reference build allocations: packed reads fewer bytes but more objects than flat, and uncached moved-descendant bound validation remains linear. The [actual-history sample](experiments/history_merge_study.py) supplements the eight [controlled disjoint-edit cases](experiments/text_merge_study.py). The [exact-cohort replay](experiments/merge_refinement_study.py) qualifies a sparse suffix index in place of the dense fallback: fourteen additional clean results and roughly 17 MiB on the formerly 310 MiB allocation probe, without raising the remaining limits. Four additional refusals versus Git/Jujutsu still hit variant/combination bounds. Qualify their refusal/re-review burden before driver freeze; do not infer general workflow benefit or raise limits merely to match baselines. Broader churn/workload and native resource behavior remain unqualified; these are not throughput or usability results. Qualify binary depth budgets on wide composition chains. Revise failed candidates before stable data, not at Milestone 5.

8. **Workflow/privacy qualification:** the [UX contract](ux.md#5-qualification-not-ux-claims) owns complete cases, not a validated user model. Compare paper interactions for addressing unfinished work before its first commit, independent recovery/commit scope, and discoverable return/recovery before freezing navigation. Then qualify immutable partial previews, stale/editor changes, deletion/coverage, exact parent intent, retention, conflict confirmation and honest errors through actual entry points as features arrive. Explicit recovery includes eligible new files; authoring still requires deliberate inclusion and subtree-deletion consent. Default source export omits private recovery/audit roots, and newly authored canonical Observation metadata must not copy unrelated private capture path inventories. The [bounded selected-authoring case](research.md#17-selective-authoring-and-private-recovery--october-29-2026) now checks those distinctions with canonical objects, not an implemented user entry point. Full-backup disclosure is broader. Later transfer/stack/review, protocol and interoperability journeys belong to their respective feature gates, not prerequisites for initial local codecs. Compare well-configured Git/Jujutsu in single- and multi-directory workflows, counting setup/navigation/cleanup, retries, re-review and wrong-server risks. Do not manufacture permanent mock-output tests before an implementation exists.

**Milestone-0 exit gate (currently NOT met):** at least two independent object codecs agree on published golden vectors; a separate pure reference model exercises the corrected structural/merge/recovery invariants; and modelled local GC/pin and workspace interleavings have no unresolved loss/cycle/ABA counterexample. Typed operation/admission semantics and representative pre-freeze layout/merge evidence must also be reviewed. Native exchange security and hosted evidence/candidate identity are their own Milestone-3/4 pre-ship gates, not prerequisites for initial local custody. Record failed cases explicitly. Correct unreleased constants and fixtures explicitly **before any persistent native data** is entrusted to them; published formats require a new identity and migration. Model checking of the concurrent state machines is a release qualification, not proof from reading this document.

## Milestone 1 — native local source custody

Build a cohesive native library/CLI from the qualified specification; the legacy Git-wrapper code, its interfaces and tests are **disposable**, with no migration or backwards-compatibility commitment. Never silently interpret a Git/prototype repository as a native one. Build the typed content objects and deterministic radix source tree, StateId, RevisionId, logical ChangeId/evolution, SQLite-only local authority with bounded segmented object staging, typed provenance and independent native export/backup. No hosted candidate objects or external large-object backend are required.

A complete local user should be able to initialize, inspect status, record a revision, list/history/diff/show exact source by ID, move/copy a subtree, reopen the repository, create a separate workspace, **preserve and resume serial work in-place with its exact history base, protected before-images and honest limitations**, and restore safely to a newly allocated directory **without Git, network or daemon**.

**Hard gates:** every acknowledged root has complete durable object closure; wrong hashes reject; no path escape or silent name collisions; equal source content produces equal canonical StateId; a no-op content write or timestamp-only observation cannot alter StateId (status/capture coverage may still change); init pins an unauthored empty State and the first commit has no parent; source export does not hydrate private audit commitments; incomplete filesystem observations are labeled honestly; recover after injected process crashes and disk-full conditions. Native verified export/backup supports independent source custody. Run actual Rust tests/lint/toolchain checks once Rust code changes.

## Milestone 2 — recoverable work and history composition

Implement distinct capture/head/selection generations, expiring recovery and explicitly pinned unfinished-work retention. Work through typed conflicts, symbolic markers with round-trip manifest, conservative content merging, rebase/amend evolution, source revert, operation undo and explicit reapply.

Cases: competing agents (choose one), compositional independent agents (combine selected changes), same-path edits, directory move/edit, delete-vs-modify, binary conflicts, already conflicted source, criss-cross multiple bases, concurrent workspace status/capture, crash between root selection and directory creation.

**Hard gates:** nested binary representation never drops/cancels an original input; an over-budget merge fails **without** an invented output State but keeps explicitly pinned inputs. No permanently clean uncontrolled files; no acknowledged capture missing bytes within retention. In-place switching requires explicit preservation policy for dirt/obstructions, refuses unknown coverage, preserves before-images and does not overwrite post-crash external edits. Preserved unfinished work survives ordinary checkpoint expiry and interrupted resume; pin release requires verified materialization plus durable recovery handoff. Exercise same-base A → B → return to A, including before either has a commit, exact original ancestry, observed tracked/new origins and registration closure without source loss. For selected edit transfer/downstack feedback, retain unrelated work and both inputs on cancellation/conflict; qualify descendant scope, split/fold mappings and incomplete outcomes before those operations ship. Conflicting proposals remain recoverable; separate workspaces incur no shared logical head contention. Tests run against **immutable built source**, not mutable worker files. Qualify the UX contract's exact selected-candidate promotion/amendment, prepared-checkpoint retention, history-only undo diagnostics and whole-unit coupled resolution rather than exposing backend state-machine terms to users.

## Milestone 3 — native source protocol and ephemeral handoff

Expose the same typed semantics in a library and native protocol: get file/range/tree by source ID, diff, history/ancestry, conditional source transform, merge, draft sync and protected target update. Implement resumable batched transfer plus sparse object hydration; full copied repositories must operate offline.

**Protocol pre-ship gate:** negotiate bounded/versioned transfer, complete-root sparse witnesses and explicit missing/promised status; qualify authorization changes, cross-tenant existence tests, path-restricted filtered responses and server-side conditional transforms. Local conditional generations, receipt retry and outbox mechanisms are qualified in the earlier local milestones, independently of hosting.

Critical end-to-end test: full client chooses source; an isolated container/microVM receives the needed immutable source (without a full history clone), edits ordinary files, submits a **durably pinned immutable private draft or deliberately authored revision** and terminates only after confirmed custody. A second machine reconstructs the submitted source and the recorded base/pending/path-origin data needed for the promised resume. Private handoff does not require authoring. Repeat under network failure, lost replies, missing partial objects, restart, authorization revocation and GC. Separately disconnect after sparse acquisition: report which exact roots/operations have complete local custody rather than treating a populated directory as offline readiness.

**Hard gates:** an unpinned upload is never reported as durable handoff; source read permission is checked on rooted closure and path scope; no raw sibling proof disclosure beyond policy; guessed hashes do not bypass authorization; no client interprets promised-but-absent as source absence; unknown submit responses are resolved through durable idempotency receipts.

## Milestone 4 — shared integration and candidate validation

Specify a separate versioned hosted candidate identity/evidence wire format (not retired local kind 9), then implement typed candidate inputs, validation attestations, shared target policy and compare-and-swap, batching selected work, accepted/verified options and durable publication receipts. Integrate native source-state equality with external test/build provenance without incorporating CI into the VCS engine.

**Hard gates:** independently reproduce exact candidate identity and authenticated evidence framing/trust; verify manual Transform replay, policy/toolchain/source freshness and complete target-owned custody. The abstract authority model covers CAS/receipt ABA only, not these hosted guarantees. Signed tests apply to exact candidate, declared environment/toolchain and trusted policy; stale target/policy/auth inputs invalidate acceptance; protected ancestry rules are checked; concurrent proposals remain preserved. A writable directory, stable ChangeId or matching before/after hashes alone cannot certify the executed input. Review integrations identify exact comparison versions/base/scope and cannot silently transfer approval through amend/rebase/evolution; qualify any explicit reuse policy without requiring a native forge. A linear target serializes **only its own** acceptance, with monotonically increasing generation and persisted receipt/outbox. Retries after unknown responses are idempotent and duplicate side effects are rejected.

## Milestone 5 — performance and platform qualification

Build on Milestone 0's pre-freeze reference cost evidence with actual engine/platform measurements. Tune physical segment sizing, compression/chunking, derived indexes and transport without changing canonical IDs. If canonical layout changes are justified after release, use explicit format migration; no silent retuning of hash inputs.

| Benchmark | End-to-end measures |
| --- | --- |
| Human edit-test-repeat, tiny and medium repos | status, revision write, diff, first read, memory and source recovery |
| Serial interruption/return versus concurrent directories | exact resumed work/base, errors, setup/navigation/cleanup, dependency/cache cost and process/server affinity |
| Private agent saves, millions of bounded captures | durable admission rate, quota behavior, retention reclamation |
| 1/8/32 independent writers | throughput/tail latency, time in physical write transactions, false logical conflicts, stale-caller recovery steps, WAL growth and GC progress |
| 100k revisions, large trees and wide directories | cold/hot path lookup, diff, subtree moves, canonical node counts, GC |
| Path-Merkle vs inode-indirected **reference study** (only if material costs emerge) | identical source edits at shallow/deep paths and large inode counts: bytes rewritten, object/node counts, read/diff/rename costs, index maintenance and history-independent StateId validation; no unmeasured canonical-model switch |
| Physical-store profiles under **equal acknowledged durability** | baseline SQLite-only segmented custody vs a future external backend only if measurements justify one, plus optional CDC/deltas: WAL/FULL sync, p50/p95/p99 admission, reader/checkpoint/GC/backup, cold hydration, bytes per capture and authored revision, delta read amplification |
| CI and remote microVMs | complete setup-to-result time, cold source acquisition, sparse API calls, transfer bytes, shared-cache effects, custody-receipt resolution |
| Native/Git contribution, review and CI (chosen adapter journey) | setup/tooling gaps, exact native/Git version mapping, returned edits, check identity, manual/repeated validation and recovery cost |
| Real merges and refactoring histories | wrong auto-merge rate, unnecessary conflict rate, latency and review burden |
| Process kill/power loss/disk full/remote outage | acknowledged source survival, staging/GC races, backup restore, recovery time |

Use comparable durability, source content and wall-clock total workflow against tuned Git/Jujutsu and relevant existing alternatives. Report software versions, machine/filesystem, raw measurements, cache warmth, retries and failures; do not present Scion/Enroute's fleet figures as AVC speedups.

**Platform qualification:** Linux filesystems, APFS and Windows have different rename/fsync/symlink/name rules. Test the supported feature subset explicitly. Treat a successful process-kill experiment as *insufficient* proof of power-loss safety. If an **optional managed/FUSE workspace** is later developed, separately test buffered/mmap writes, open-handle and inode/cache invalidation across root switches, true fsync/fdatasync/fsyncdir behavior, uncertain unmount, crash recovery and time-to-durable-capture receipts. It must not become a prerequisite for ordinary workspaces.

## Deferred independent questions

Engineering qualification and discretionary integrations remain: published **independent codec vectors and parser limits are mandatory Milestone-0 gates**, not optional physical optimizations. LayerFS comparisons are **later physical/workspace qualification**, not new Milestone-0 blockers or evidence for replacing AVC's canonical State representation. Physical blob/chunk compression, future source-metadata expansion, hosted cache layout and a Git interoperability interface (conversion, synchronized bridge or protocol-facing adapter) and an optional Fossil-like `avc web` viewer over the native APIs are deferred interfaces. Git interoperability must report unsupported/lossy cases and preserve native export as the full-fidelity custody path; it is not a promise of native Git-compatible IDs or lossless arbitrary-history round trips. The **4096-byte canonical map leaf rule and nibble partition** are defined rules of the current candidate codec, not runtime tuning knobs. They remain subject to the pre-freeze evidence gate; after release, changing them changes format identity. Keep the project named AVC; do not add a required Git-compatible mode, hosted forge, process sandbox, or custom consensus layer.

**Release rule:** trust source integrity, explicit undo/merge behavior, capture/restore honesty and independent export/backup before encouraging users to entrust irreplaceable code. No native implementation or verified production speedup is implied by this design package.
