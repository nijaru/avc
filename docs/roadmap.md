# AVC — design qualification and delivery roadmap

**Revised 2026-10-27.** [Design](design.md) is the selected v0 architecture; [research](research.md) records evidence and rejected choices. The format is *not yet published/stable* and the current Rust 0.0.1 code remains an unrelated Git-command prototype.

Qualify the selected native semantics rather than restarting a general VCS search. Product invariants and implementation choices have different status: correct demonstrated failures and evaluate consequential representation costs before format freeze. Git conversion is a deferred boundary adapter, not a native Git-compatible backend. No native engine is implemented by this plan.

## Milestone 0 — independently verify the selected contracts

**2026-10-16 checkpoint (partial):** The independent [Python fixture codec](experiments/codec_reference.py) and [Node.js cross-check](experiments/codec_crosscheck.mjs) agree on **all 27 pinned golden vectors** across nine kinds and 110 typed objects, with separately implemented BLAKE3 functions checked against published vectors. The Python suite now has **17 passing tests**, including **32 seeded cross-language randomized radix maps**, 200 individually re-hashed single-byte mutation probes, contextual nibble decoding, 4095/4096/4097 leaf boundaries and nested conflict-root validation. A real reference decoder bug admitted a root conflict containing a hidden nested deletion; it is now covered by regressions. Run `python -m unittest discover -s docs/experiments -p 'test_codec.py' -v` and `node docs/experiments/codec_crosscheck.mjs`. **Exit gate remains unmet:** native Rust codec agreement, comprehensive fuzz/property verification, independent merge/source semantic models and crash/concurrency qualification remain.


**2026-10-27 correction:** The Python codec suite has **22 passing tests**, including differential admission of the same exact object corpus by Node: conflict depth through directories, singleton collapse at 4096/4097 alternatives and raw-path provenance ordering. All 27 pinned IDs remain unchanged. The separate [text reference](experiments/text_merge_reference.py) has **four passing tests**, including exhaustive alignment comparison for 961 small sequence pairs and a 2001-line distant-edit merge. These are finite reference checks, not parser security, real workspace or durability qualification.

The [authoritative design](design.md) owns source authority, typed objects, candidate codec/layout, conflict grouping, workspace/recovery and commit/GC ordering. Before permanently writing native user data, qualify these contracts with **independent** decoders/models and golden vectors:

1. **Canonical typed object encoding (Python/Node vectors agree; native Rust verification outstanding):** independently reproduce BLAKE3 framing, **typed external ID**, kinds 1–9, exact 4096-byte leaf-size inequality, nibble prefix compression and parent-context parity, fixed-width lengths, path bounds and canonical map reconstruction. Publish and cross-check byte+hash vectors for empty map/source, files, symlinks, prefix-name pairs, threshold branches, odd-nibble boundary, directory moves, root conflicts, grouped conflicts, Revision/Provenance and PublicationCandidate; reject hash mismatches, missing closure, bad padding, invalid root types and noncanonical alternate trees. Two independent decoders/builders must agree before the first **durable native repository** is created.
2. **Pure source model:** independently check Put/Remove/CopySubtree/MoveSubtree as a conditional two-phase structural+leaf transaction, including exact old/absent witnesses, overlapping/swap rejection, relocated **descendant path-bound proofs** and retention of referenced copy sources. Random edit order yielding the same logical tree must produce the same StateId. Test huge directories, ancestor/descendant keys and all 4095/4096/4097 leaf boundaries.
3. **Conflict source algebra:** independently exercise equality/base rules, **unique-optimum sparse match-pair LCS** with content-derived budgets (not whole-file cell counts), transient execution failure without an output State, exact hunk boundaries, CRLF/duplicate-lines and text/binary/mode/type cases; verified user-recorded moves versus heuristic lookalikes, **new additions under renamed directories**, and deletion/rename coupled subtree/root conflicts. Confirm **width >64** canonical kind-8 grouping, **recursively present directory alternatives in a State-root conflict**, and that **nesting >64/graph-budget overflow refuses** a new State with protected input roots. Model criss-cross frontier reduction with virtual ancestry, already-conflicted inputs and absent/non-directory descendants; read unaffected siblings without wrongly assuming a missing sparse object is absence. Marker round-trip cannot resolve conflicts implicitly.
4. **Revision evolution:** divergent amendments, single-parent rebase, split/fold explicit lineage, and generational operation undo versus exact **inverse-content revert/reapply** formulas, including multi-parent mainline selection. Verify separate Revision/State/ChangeIds, canonical revision/provenance acyclicity and the separately owned evolution graph, including expired endpoints; reject unrequested descendant rewrites and undefined merge-commit rebases.
5. **Workspace and capture state machine:** separate selection/capture/materialization generations, acknowledgement and retention pins, observation coverage, watcher gaps and honest writer-quiesced labels. Check capture promotion against its exact recorded parent (never an equal-State lookup), explicit partial coverage, fresh ChangeId/idempotent retries and preserved observation provenance. Test unknown untracked obstacles, symlink containment, dirty/clean races, journal and marker-manifest durability before the first mutation, unchanged/edited/missing-manifest marker capture without implicit resolution, guarded inode/path replay, verification timestamps and `Incomplete` recovery after process kill. Distinguish strong **fresh-directory** no-clobber restore from inherently racy **in-place** switches.
6. **Object durability and GC (bounded authority model landed):** [Finite-state tests](experiments/authority_model.py) independently enumerate one-object reader/stage/root/backup/GC interleavings, expose stale-mark deletion after a pin/root, and exercise transactional tombstones, directory-fsync-before-root ordering assumptions and publication CAS/receipt ABA. **This is not a disk/fsync implementation.** Next prove the full multi-object closure invariant against real SQLite WAL/FULL + external files. Inject real file/dir fsync, GC/object install/path-reuse races, orphan staging, receipt retries, backup leases and reconstructable export/restore.
7. **Native exchange security:** distinguish proven absence from promised/missing objects; validate complete-root sparse witnesses, **do not disclose raw siblings to path-restricted clients**, and verify server-side scoped transforms under authorization changes. Exercise bounded resumable bundles, cross-tenant guessed-ID queries, and durable pinned draft **receipt+closure** before microVM termination.
8. **Shared acceptance:** independently reproduce kind-9 PublicationCandidate byte identity and validation evidence bound to it; check policy/toolchain/source freshness, server-verifiable **manual transform recipes**, protected ancestry and authorization. The [abstract authority model](experiments/authority_model.py) already checks single-target generation ABA, unknown-result receipt retries and one durable outbox event per accepted key; it does **not** qualify authorization, persistence or real delivery. Extend with authenticated evidence, durable target transactions and at-least-once outbox delivery/deduplication. Specify signed evidence format and validator trust policy **before** the publication protocol ships.

9. **Recipe and cost qualification before format freeze:** specify canonical schemas for every executable structural/merge/observation/manual-publication recipe in the existing design owner; cross-check exact base/side bindings, frontier/virtual traces and pinned execution dependencies. Unknown recipe bytes remain inspectable but cannot authorize execution. Compare the candidate radix representation with ordinary Git-shaped trees on representative narrow/wide/deep edit, lookup, diff and move traces; measure canonical bytes rewritten, node counts and reference working memory without claiming engine throughput. Measure sparse-driver ambiguity/budget fallback on real merge histories. Revise failed candidate constants before stable data, rather than waiting for Milestone 5.

**Milestone-0 exit gate (currently NOT met):** at least two independent object codecs agree on published golden vectors; a separate pure reference model exercises the corrected structural/merge/recovery invariants; and modelled GC/pin, workspace and publication interleavings have no unresolved loss/cycle/ABA counterexample. Executable recipe schemas and representative pre-freeze layout/merge evidence must also be reviewed. Record failed cases explicitly. Correct unreleased constants and fixtures explicitly **before any persistent native data** is entrusted to them; published formats require a new identity and migration. Model checking of the concurrent state machines is a release qualification, not proof from reading this document.

## Milestone 1 — native local source custody

Build a cohesive native library/CLI from the qualified specification; the legacy Git-wrapper code, its interfaces and tests are **disposable**, with no migration or backwards-compatibility commitment. Never silently interpret a Git/prototype repository as a native one. Build the typed content objects and deterministic radix source tree, StateId, RevisionId, logical ChangeId/evolution, local SQLite metadata authority and small-object store.

A complete local user should be able to initialize, inspect status, record a revision, list/history/diff/show exact source by ID, move/copy a subtree, reopen the repository, create a separate workspace, **switch in-place with protected before-images and honest limitations**, and restore safely to a newly allocated directory **without Git, network or daemon**.

**Hard gates:** every acknowledged root has complete durable object closure; wrong hashes reject; no path escape or silent name collisions; equal source content produces equal canonical StateId; a no-op content write or timestamp-only observation cannot alter StateId (status/capture coverage may still change); incomplete filesystem observations are labeled honestly; recover after injected process crashes and disk-full conditions. Native verified export/backup supports independent source custody. Run actual Rust tests/lint/toolchain checks once Rust code changes.

## Milestone 2 — recoverable work and history composition

Implement distinct capture/head/selection generations and bounded retention. Work through typed conflicts, symbolic markers with round-trip manifest, conservative content merging, rebase/amend evolution, source revert, operation undo and explicit reapply.

Cases: competing agents (choose one), compositional independent agents (combine selected changes), same-path edits, directory move/edit, delete-vs-modify, binary conflicts, already conflicted source, criss-cross multiple bases, concurrent workspace status/capture, crash between root selection and directory creation.

**Hard gates:** width grouping never loses a term; an over-budget merge fails **without** an invented output State but keeps explicitly pinned inputs. No permanently clean uncontrolled files; no acknowledged capture missing bytes within retention. Default in-place switching refuses dirty/untracked/unknown obstructions, preserves before-images and does not overwrite post-crash external edits. Conflicting proposals remain recoverable; separate workspaces incur no shared logical head contention. Tests run against **immutable built source**, not mutable worker files.

## Milestone 3 — native source protocol and ephemeral handoff

Expose the same typed semantics in a library and native protocol: get file/range/tree by source ID, diff, history/ancestry, conditional source transform, merge, draft sync and protected target update. Implement resumable batched transfer plus sparse object hydration; full copied repositories must operate offline.

Critical end-to-end test: full client chooses a revision; an isolated container/microVM receives the needed immutable source (without a full history clone), edits ordinary files, submits a **durably pinned immutable authored revision** and terminates; a second machine reconstructs exactly the submitted source. Repeat under network failure, retries, missing partial objects, restart, authorization revocation and GC.

**Hard gates:** an unpinned upload is never reported as durable handoff; source read permission is checked on rooted closure and path scope; no raw sibling proof disclosure beyond policy; guessed hashes do not bypass authorization; no client interprets promised-but-absent as source absence; unknown submit responses are resolved through durable idempotency receipts.

## Milestone 4 — shared integration and candidate validation

Implement candidate/recipe identities, validation attestations, shared target policy and compare-and-swap, batching selected work, accepted/verified options and durable publication receipts. Integrate native source-state equality with external test/build provenance without incorporating CI into the VCS engine.

**Hard gates:** signed tests apply to exact candidate, declared environment/toolchain and trusted policy; stale target/policy/auth inputs invalidate acceptance; protected ancestry rules are checked; concurrent proposals remain preserved. A linear target serializes **only its own** acceptance, with monotonically increasing generation and persisted receipt/outbox. Retries after unknown responses are idempotent and duplicate side effects are rejected.

## Milestone 5 — performance and platform qualification

Build on Milestone 0's pre-freeze reference cost evidence with actual engine/platform measurements. Tune physical file/blob thresholds, compression/chunking, derived indexes and transport without changing canonical IDs. If canonical layout changes are justified after release, use explicit format migration; no silent retuning of hash inputs.

| Benchmark | End-to-end measures |
| --- | --- |
| Human edit-test-repeat, tiny and medium repos | status, revision write, diff, first read, memory and source recovery |
| Private agent saves, millions of bounded captures | durable admission rate, quota behavior, retention reclamation |
| 1/8/32 independent writers | throughput, time spent in physical write transactions, false logical conflicts |
| 100k revisions, large trees and wide directories | cold/hot path lookup, diff, subtree moves, canonical node counts, GC |
| Path-Merkle vs inode-indirected **reference study** (only if material costs emerge) | identical source edits at shallow/deep paths and large inode counts: bytes rewritten, object/node counts, read/diff/rename costs, index maintenance and history-independent StateId validation; no unmeasured canonical-model switch |
| Physical-store profiles under **equal acknowledged durability** | baseline hybrid SQLite/external vs all-in-SQLite placement and optional physical CDC/deltas: WAL/FULL sync, p50/p95/p99 admission, reader/checkpoint/GC/backup, cold hydration, bytes per capture and authored revision, delta read amplification |
| CI and remote microVMs | cold source acquisition, sparse API calls, transfer bytes, shared-cache effects |
| Real merges and refactoring histories | wrong auto-merge rate, unnecessary conflict rate, latency and review burden |
| Process kill/power loss/disk full/remote outage | acknowledged source survival, staging/GC races, backup restore, recovery time |

Use comparable durability, source content and wall-clock total workflow against tuned Git/Jujutsu and relevant existing alternatives. Report software versions, machine/filesystem, raw measurements, cache warmth, retries and failures; do not present Scion/Enroute's fleet figures as AVC speedups.

**Platform qualification:** Linux filesystems, APFS and Windows have different rename/fsync/symlink/name rules. Test the supported feature subset explicitly. Treat a successful process-kill experiment as *insufficient* proof of power-loss safety. If an **optional managed/FUSE workspace** is later developed, separately test buffered/mmap writes, open-handle and inode/cache invalidation across root switches, true fsync/fdatasync/fsyncdir behavior, uncertain unmount, crash recovery and time-to-durable-capture receipts. It must not become a prerequisite for ordinary workspaces.

## Deferred independent questions

Engineering qualification and discretionary integrations remain: published **independent codec vectors and parser limits are mandatory Milestone-0 gates**, not optional physical optimizations. LayerFS comparisons are **later physical/workspace qualification**, not new Milestone-0 blockers or evidence for replacing AVC's canonical State representation. Physical blob/chunk compression, future source-metadata expansion, hosted cache layout and a Git import/export boundary adapter and an optional Fossil-like `avc web` viewer over the native APIs are deferred interfaces. Git conversion must report unsupported/lossy cases and preserve native export as the full-fidelity custody path; it is not a promise of native Git-compatible IDs or lossless arbitrary-history round trips. The **4096-byte canonical map leaf rule and nibble partition** are defined rules of the current candidate codec, not runtime tuning knobs. They remain subject to the pre-freeze evidence gate; after release, changing them changes format identity. Keep the project named AVC; do not add a required Git-compatible mode, hosted forge, process sandbox, or custom consensus layer.

**Release rule:** trust source integrity, explicit undo/merge behavior, capture/restore honesty and independent export/backup before encouraging users to entrust irreplaceable code. No native implementation or verified production speedup is implied by this design package.
