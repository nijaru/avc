# AVC research — decisions and rejected architectures

**Decision review: 2026-10-27.** The [design](design.md) is authoritative; the [verification plan](roadmap.md) defines qualification. This research is an evidence and trade-off record, **not** native AVC performance measurements. Dated audits retain their then-tested assumptions; [section 11](#11-from-scratch-simplification-review--october-27-2026) supersedes the hybrid store, width groups, opaque recipes and initial-core candidate schema. The [UX review](#12-user-workflows-and-private-history-boundaries--october-27-2026) further corrects provenance custody; the architecture contract lives in design.md and user interactions in ux.md.

## 1. What matters most

Optimize complete source-development tasks rather than raw commits/s. A general-purpose VCS must work for arbitrary filesystem writers on laptops and VPSs, offline projects, persistent remote workspaces, speculative agent tasks, short-lived microVMs/containers, CI, and hosted large repos.

Two distinctions resolve much of the previous indecision:

- **Private captures are not authored revisions.** An agent can generate thousands of recoverable intermediate edits without creating thousands of permanent shared changes or triggering CI. Optimize capture admission and retention independently of authored source history.
- **Source representation does not determine execution location.** A snapshot-root model can serve checkout-free queries, sparse clients, remote agents and highly distributed caches. A delta-root model can run locally. Hosted scale alone does not select canonical history.

The central safety question is: *what exact bytes can the tool reconstruct and protect after this operation?* A VCS that optimizes writes without proving its declared source state is valid and durable is not better.

## 2. Canonical models evaluated

| Model | Strongest advantage | Main drawback for AVC | Decision |
| --- | --- | --- | --- |
| **A. Canonical persistent State tree plus Revision DAG** | Exact historical source root immediately available; opaque files; subtree reuse; simple source trust boundary | Build persistent tree nodes for each authored revision; canonical codec becomes long-term commitment | **Select** |
| **B. Canonical parent-relative changed-file log plus derived source trees** | Admit valid but rarely viewed revisions without storing each root; derived tree encodings can evolve freely | Must still validate source/preconditions; cold reads can replay long history; subtree moves need careful treatment | Reject as the primary history model; use deltas for capture, efficient transfer and change hints |
| **C. Canonical causal patch/file graph plus materialized source** | Selective causal undo and stronger commutation for supported operations | Infer no unique edit intention from arbitrary filesystem bytes; complex rename/delete/binary/reference-retention rules | Do not impose on general source truth; use specialized editing tools if necessary |

**Why A wins on the specified product:** Most meaningful authored revisions get inspected, tested, merged, transmitted or otherwise require an exact source view. An immutable Merkle tree shares all unchanged subtrees. A source snapshot does not store a complete physical copy on every change. A subtree move can reuse immutable bindings without rebuilding 100,000 descendants, but relocated path-bound validation still needs a complete traversal or an already validated summary of the exact subtree.

**Real disadvantage:** A requires a stable canonical directory representation. AVC therefore *selects* one bounded deterministic Merkle radix structure and accepts future explicit format migration, instead of using a flat map forever or pretending tree encoding is an optional derived index.

**Where B could win:** An unusually large stream of already validated, durable authored revisions that are almost never read. Anthropic's hosted workload is closer to that scenario; an ordinary human or agent completing a task often immediately needs the source to test it. A source-delta record must still have a valid base and a valid resulting namespace. Deferring all validation until someone reads the revision means acknowledging a pending draft, not a complete trustworthy source state.

The [reference model](experiments/source_models_oracle.py) has deterministic in-memory checks (including 250 edits compared to a separate flat path model). It verifies that a checked delta interpreter and a snapshot interpreter can reconstruct identical source, and that an invalid delta must not be acknowledged as a coherent revision. **It neither compares real storage performance nor proves final radix/merge semantics.**

**Where C could win:** Systems needing causal selective undo of identical independently authored text and strongly commuting editor operations. [Pijul's change theory](https://pijul.org/manual/theory.html) and [Darcs patch algebra](https://darcs.net/Theory/MergersDocumentation) demonstrate real alternatives. Their strongest guarantees depend on the supported editing algebra. Arbitrary editors, binaries and external file-generating tools don't record such operations. AVC cannot pretend to reconstruct causality from final bytes alone.

## 3. Primary-source lessons without incumbent overfitting

### Git and GitHub

[Git objects](https://git-scm.com/book/en/v2/Git-Internals-Git-Objects), [Git pack layout](https://git-scm.com/docs/gitformat-pack), [checkout-free merge-tree](https://git-scm.com/docs/git-merge-tree) and [commit graph](https://git-scm.com/docs/git-commit-graph) already implement immutable sharing, physical deltas, checkout-free merges, and ancestry/changed-path acceleration. Those properties are *not* AVC inventions.

[GitHub's October 2026 writeup](https://github.blog/engineering/architecture-optimization/building-git-infrastructure-for-agent-scale-development/) describes agent push/CI growth and independently scalable durable storage with Git logical history unchanged. It is a counterexample to arguments that agent growth requires a causal graph or canonical file-delta history.

### Jujutsu

[Jujutsu architecture](https://docs.jj-vcs.dev/latest/technical/architecture/), [operation log](https://docs.jj-vcs.dev/latest/operation-log/) and [first-class conflicts](https://docs.jj-vcs.dev/latest/conflicts/) demonstrate stable logical changes, operation recovery, concurrency and multi-sided symbolic conflicts. It is AVC's primary user-semantics baseline. AVC's proposed benefits must come from the complete recovery/workspace/source-API/integration workflow rather than naming or reimplementing these features. The architecture page also documents concrete Git-backend costs: extra ChangeId/predecessor metadata, `refs/jj/keep/` retention refs and an identity collision when two commits differ only in ChangeId. Those are reasons to evaluate native identity, not proof that new semantics cannot be implemented on Git objects.

### Anthropic Scion and Meta Mononoke

[Scion (October 13, 2026)](https://www.anthropic.com/engineering/redesigning-source-control) describes canonical changed-file records, derived trees/history/blame, API-first computation, sparse cached clients and narrow shared ref CAS. It reports more than 30,000 changes/day and around 25 million CI checkouts/day plus large improvements against prior Git-mirror infrastructure. The authors note their *first-parent* changed-file format is a stylistic trunk-workflow choice; their speedups do **not** isolate a canonical-delta-versus-snapshot comparison at equal cache/durability/network cost.

[Mononoke's Bonsai data model](https://github.com/facebook/sapling/blob/main/eden/mononoke/docs/2.1-bonsai-data-model.md), [derived indexes](https://github.com/facebook/sapling/blob/main/eden/mononoke/docs/2.3-derived-data.md), and [Bonsai source type](https://github.com/facebook/sapling/blob/main/eden/mononoke/mononoke_types/src/bonsai_changeset.rs) establish closely related canonical changed-file/derived-data techniques. These are distinct operational deployments but **not independent controlled evidence** for B's universal superiority. Disputes over specific design influence do not establish technical optimality.

**Take the useful principles:** no-checkout APIs, optionally asynchronous blame/path indexes, sparse and lazy working copies, immutable content caches and short ref transactions. Each works with the selected State-root architecture.

### Enroute and Cursor

[Enroute storage](https://github.com/enroute-sh/enroute/blob/main/docs/internals/storage.md), [fetch algorithms](https://github.com/enroute-sh/enroute/blob/main/docs/internals/read-path.md) and [Cursor Git-at-scale](https://cursor.com/blog/git-at-any-scale) demonstrate that physical storage, compaction, distributed read-serving and publication can improve dramatically without altering canonical history. Enroute's dense object numbering, commit segments and Raft log solve its hosted Git workload. **Do not transplant them** as AVC's canonical IDs or mandatory coordination mechanism.

### WalGit

[WalGit's README](https://github.com/tobi/walgit/blob/main/README.md) and [goals](https://github.com/tobi/walgit/blob/main/GOAL.md), checked October 27, 2026, describe a Git host built on Cursor's Continuity design: immutable push packs/log entries, conditional manifest publication and disposable serving caches over an object store. This is another concrete counterexample to equating agent-scale hosting with a need for a new canonical source format. It is not a replacement for AVC's local workspace/capture/conflict semantics, and no AVC comparison was run. Reuse the separation of durable custody, short publication decisions and serving caches; do not import an object-store requirement or claim that conditional object writes remove the storage provider's consistency obligations. AVC's Git boundary is conversion, not native compatibility.

### Persistent directory structures

[Meta's Sharded Map V2](https://github.com/facebook/sapling/blob/main/eden/mononoke/docs/2.3-derived-data.md) uses path-compressed tries, bounded nodes and small inline terminals. This directly supports AVC's native directory map choice.

[Dolt's Prolly Tree fast merge](https://www.dolthub.com/blog/2025-07-16-announcing-fast-merge/) demonstrates both good ordered-map sharing and complications when chunk boundaries move. Prolly is a strong alternative for certain tables and ordered ranges, but hierarchical source names and subtree moves favor deterministic prefix partitioning with bounded small leaves.

### Merge and collaborative editing

[2026 MergirafSemi](https://arxiv.org/abs/2608.11345) documents a genuine tension between reducing apparent conflicts and allowing incorrect automatic combinations. AVC prioritizes preserving uncertain alternatives. [Eg-walker (EuroSys 2025)](https://martin.kleppmann.com/2025/03/30/eg-walker-collaborative-text.html) informs optional causal collaborative text editors, but does not provide arbitrary file tree or binary semantics.

### Local durability

[SQLite synchronous/WAL documentation](https://www.sqlite.org/pragma.html#pragma_synchronous) distinguishes the failure assumptions of FULL and NORMAL durability. A transactional local metadata authority and protected immutable objects reduce new trusted code versus a custom consensus/journal implementation. The current SQLite-only baseline must still handle bounded staged segments, reader/GC leases, short admission transactions and backup closure. Workspace materialization and native exported files retain their separate filesystem-sync obligations.

## 4. A coherent design, not a feature inventory

AVC has **one authority per type of fact**:

| Fact | Authority | Other representations |
| --- | --- | --- |
| Exact source | Content-addressed State objects | Changed paths and diffs are derived/verified |
| Authored history | Immutable Revision DAG | Stable logical ChangeId and evolution links |
| Unfinished recovery | Protected time-bounded Capture | Cannot claim a complete authored revision unless promoted/validated |
| Working-directory selection | Workspace selection generation | Files on disk are external observations; status is fallible |
| Shared acceptance | Per-target transactional root | Tests/reviews are evidence about exact immutable candidates |
| Build/deployment | External execution/artifact system | AVC may reference their provenance but does not own process state |

The model does not need a permanent authoritative delta log plus an authoritative snapshot log plus an agent-operation log. Private captures may be stored *incrementally* without being a second version of canonical authored source.

A metadata-only or sparse agent can inspect an immutable StateId without obtaining an entire local repository. A full local repo remains self-contained and offline. A short-lived remote agent can commit/pin its exact new source before discarding its VM. These outcomes follow from immutable source IDs, resource-scoped durability and native APIs, **not from adopting Scion's or Enroute's physical encodings**.

## 5. Costs and overturn conditions

Decisions are selected, but engineers should not pretend proven metrics:

- **Snapshots:** pay tree construction when recording authored history. A measured highly speculative workload could motivate a cheaper draft representation; AVC already has captures/pending edits for this.
- **Radix map:** larger per-node overhead and key-prefix processing than carefully paged POS structures in some workloads. Compare consequential alternatives before freezing the candidate; after release, canonical changes require migration.
- **Typed conflicts:** multiway normalization, merge-base recursion and marker presentation are hard. Preserve all alternatives and fail closed on complexity limits.
- **Metadata in revision IDs:** changing a description can rewrite descendant IDs; stable logical ChangeId helps user identity but does not remove rewrite computation.
- **SQLite authority:** excellent local correctness starting point, not a distributed hosted database. Hosted target/root authority uses its own storage while preserving logical CAS.
- **No Git compatibility:** frees the native model but costs adoption and existing tooling integration. Self-contained native backup/export is mandatory; third-party bridges are elective.

The existing [contract probes](experiments/vcs_contract_probes.py) record wrong merge assumptions, stale filesystem overwrite, staged-object collection and global-head contention. They are counterexamples, not production VCS tests.

**Before format freeze:** qualify selected representations against correctness, essential workflows and representative costs; a prior selection is not evidence that its constants are best. Revisit consequential failures or material comparative evidence without restarting product selection over each new article. After release, canonical changes need explicit format migration rather than silent retuning.

Prior incompatible architectural proposals remain accessible through Git history. The present [design](design.md) supersedes them; no parallel "maybe canonical deltas" roadmap remains.


## 6. Adversarial architecture review — October 15, 2026

This is a **static adversarial review of the proposed contracts**, not a claim of proof or benchmark superiority. It forced concrete changes to the authoritative [design](design.md).

The responses below describe the October 15 hybrid/grouped candidate, not the superseding section-11 simplifications.

| Attack on the original idea | Counterexample | Response at that review |
| --- | --- | --- |
| "One conflict per path is enough" | Both sides rename one source to different destinations, coupling several paths | Represent conflicting subtree alternatives at their least common ancestor, including the whole-root case |
| "Source conflicts include their origin" | Two histories yield identical unresolved byte alternatives | Hash value-only conflict terms in State; store driver and input RevisionIds in separately owned immutable provenance |
| "Flatten all nested conflicts" | Criss-cross and repeated rebases can cancel meaningfully distinct alternatives | Simplify only proven equal/base cases; group only by **width**; depth/budget overflow fails admission and retains protected inputs rather than inventing an undecodable State |
| "An enormous conflict is a single blob" | 10,000 alternatives or arbitrarily deep nested conflicts consume unbounded memory | Kind-8 canonical groups handle **many distinct alternatives**; over-depth/over-budget merges return protected `MergeTooComplex` proposals, not a fake admitted source |
| "Root can only be a directory" | Root is least common ancestor of two coupled rename conflicts | State root allows a typed unresolved *directory-valued* conflict |
| "Conflict at root hides all source" | Most files are unaffected by a single rename collision | Read paths across all alternatives; return resolved value if every alternative agrees, typed uncertainty otherwise |
| "Merger picks any common ancestor" | Criss-cross history has more than one best merge base; a state-only virtual merge has no ancestry for later bases | Compute full maximal frontier; use ephemeral **virtual ancestry nodes** throughout the sorted reduction, memoize recursion and record exact recipe |
| "Same bytes means same causal effect" | Independent identical deletion then revert | State dedup means value equality, not causal selective undo. Preserve origin and allow explicit reapply |
| "Large moves require file-level deltas" | Rename directory with 100,000 files | Immutable child-directory map binding reuse; copy by content SubtreeId instead of pinning dead revision ancestry |
| "Radix choice is enough" | Threshold-crossing map yields different hashes by insertion order | Fixed deterministic maximal-prefix nibble radix split; leaf/branch constraints and byte grammar are part of canonical identity |
| "Every checkout creates a new directory" | Ordinary developers switch revisions frequently in one editor | Restore/new workspace uses strong fresh-directory guarantee; ordinary in-place switch allowed with protected before-images, refused known dirt, and honest external-writer race limitations |
| "The DB transaction protects live files" | Editor writes after scan or keeps a descriptor across rename | Selected immutable root is independent of external observed filesystem; status is time-scoped, in-place exclusion is explicitly limited |
| "Uploaded bytes means agent work is saved" | Worker VM dies after sending unpinned object files | Required protected draft root and whole source dependency closure must be acknowledged before VM deletion |
| "Unchanged diff paths imply valid program" | Agent edits API while another edits caller, with no text conflict | Validate exact integrated State under a declared toolchain/policy, CAS accepted target against observed generation |
| "CAS is one global operation head" | Capture watcher races independent workspace selection | Separate selection, capture and materialization generations; only same named shared target competes logically |
| "Content hash means trusted source" | Guessable hashes and raw sparse Merkle nodes disclose unauthorized neighbors | Closure-scoped auth, filtered path responses instead of unsafe raw proofs, symlink-safe materialization and no implicit hooks |
| "Staged object GC is harmless" | An old unmarked object is **re-pinned after** GC's mark snapshot but deleted by a late sweep | GC tombstone/admission interlock under the same transactional authority, plus pinned staging, readers and backups |
| "Offline and cloud demand different canonical stores" | Same source created locally then queried remotely | One native content ID model; full, partial and service clients differ in transport and retained closure, not source semantics |

### Research that sharpened this review

- [Dolt, September 8, 2026: Can Radix Trees Replace Prolly Trees?](https://www.dolthub.com/blog/2026-09-08-can-radix-trees-replace-prolly-trees/) distinguishes radix prefix-partition advantages from prolly's balanced pages and comparator flexibility. AVC keys are **raw byte names**, making radix ordering natural, but this does not prove best latency for every workload. v0 chooses one deterministic radix implementation so source identity is implementable; physical paging remains independent.
- [Jujutsu's technical conflict model](https://github.com/jj-vcs/jj/blob/main/docs/technical/conflicts.md) explains nested merge terms and the deliberate **lossiness** of its same-change rule in some repeated rebase scenarios. AVC explicitly keeps source-value equality separate from authorship/causal undo, and refuses arbitrary cancellation of nested unresolved conflicts.
- [Git merge-tree](https://git-scm.com/docs/git-merge-tree) demonstrates checkout-free recursive merge bases and warns that many-to-many rename/directory conflicts cannot be reduced to one conflicted-file marker. AVC models coupled source regions rather than using markers as authoritative files.
- [Microsoft Research YoloFS, April 2026](https://www.microsoft.com/en-us/research/publication/dont-let-ai-agents-yolo-your-files-shifting-information-and-control-to-filesystems-for-agent-safety-and-autonomy/) studies agent destructive filesystem effects. AVC is not an agent filesystem, but its optional protected draft/staging and explicit writer control boundaries let a VM/filesystem security layer integrate without making process state canonical source.

### Findings and limit

The review reinforces the **single source State authority**, stable Revision/ChangeId split, independently retained recoveries, and target-scoped publication. It also exposes an ergonomics tradeoff that the previous spec buried: requiring a fresh directory for *every* human branch switch is not acceptable in a general-purpose VCS, while claiming no data loss under arbitrary concurrent external writes is physically impossible. The [design](design.md) now offers both an ordinary guarded in-place switch and a separately stronger fresh-directory restore, with different stated guarantees.

**Still requiring proof** rather than architectural re-voting: independent byte/hash vectors and rooted radix normalization, structured conflict algebra and multi-base fixtures, safe switch/recovery after partial writes, durable object admission/reclamation during concurrent pinning, path authorization, and platform/performance qualification. These are concrete gates in [roadmap](roadmap.md), not evidence that a wholesale VCS model change is needed.


## 7. Independent contract audit — October 15, 2026

**Historical scope (superseded where noted in section 11):** A second adversarial *static* review of [the canonical v0 contract](design.md) found genuine underspecification and contradictions **inside** the selected architecture. These are specification corrections, **not** new evidence that canonical change-deltas or causal patch graphs are superior. No native implementation, model-checker proof, independent hash vectors, crash rig or benchmark was run in this review.

| Counterexample against the prior contract | Corrected v0 decision and remaining cost |
| --- | --- |
| A MapLeaf under an odd nibble edge is valid only with its parent prefix, but the old reader appeared to validate any MapId in isolation. | The construction function and leaf-size inequality are exact; validate map suffixes with enclosing directory/root prefix parity and full names. A bare MapId is not a standalone full-path namespace proof. Exhaustive independent codec verification remains. |
| The displayed ID omitted object kind even though kind tags are part of every reference. | Define typed `(kind, digest)` identity and unambiguous kind-bearing external spelling; preserve the original hash envelope. |
| The conflict pseudostructure had an `opaque_nested_terms` field absent from the binary payload. A 64-deep conflict cannot be made legal merely by wrapping it in another ConflictGroup. | Remove the unencoded field; group only over **width >64**; if depth/expansion exceeds limit, do **not** acknowledge a new State—return a protected, inspectable pending merge with exact input roots. This trades high-depth auto-merge completeness for an honest lossless failure. |
| Reducing 3+ merge bases by folding resulting States discards their ancestry, so later recursive base calculations have no defined input graph. | Ephemeral virtual revisions with explicitly defined ancestry, sorted reduction order, memoized frontier recursion and a bounded refusal case. It remains non-associative; no false causal cancellation. |
| Automatically using a unique exact-content deleted/added file pair as a move confuses *matching bytes* with *recorded identity*. | Only explicitly recorded source moves authorize automatic relocation of *base-descendant* competing edits under checked one-to-one mappings; ambiguous new additions under the old directory name and collisions become coupled conflicts. Inferred moves are user-confirmable hints. |
| Myers tie-breaking did not define a total portable algorithm and repeated lines can put an edit at different base anchors. | Require **unique** optimal alignment before nontrivial auto-combination and reject overlap/ambiguous cases. The later October 27 correction below replaces the dense cell cap with exact sparse match-pair LCS; a tie-break cannot affect output when ambiguous alignments are refused. Conservatively rejecting insertions at replacement boundaries remains intentional. |
| Both sides replacing a file with different directories were recursively merged although the old base was *not* a directory. | Only recurse through three directories, or independent additions into two directories from a **known absent** base; otherwise retain a typed kind conflict. |
| A successful GC mark may precede a new pin on an *old* previously unmarked object. GC's stale sweep would still delete it. | Serialize final per-object `Deleting` tombstone decisions against **current** pins, root admissions and reader leases in SQLite; deny acquisition of reclaiming objects and restage/retry. A mark snapshot alone is not a protection barrier. |
| An online SQLite snapshot could outlive its external blob references after an unrelated collector run. | Snapshot-root backup lease before releasing the root-set snapshot, plus a verified independent export manifest/closure. |
| Raw sparse leaf/branch witnesses disclose sibling names and hashes outside a path grant. | Authorized complete-closure clients may verify full Merkle witnesses. Path-restricted clients get server-verified filtered answers and conditional transforms; plain unkeyed hashes cannot promise secrecy of equality when both IDs are known. |
| An in-place switch journal did not say what to do with untracked children or edits after a partial crash. | Refuse untracked/unknown obstructions by default, protect before-images before writing, guard intended operation/selection generations, and **never** blindly roll back over newly observed external work. Incomplete journals remain recoverable, with fresh-directory restore the stronger path. |
| A publication candidate had no normative stable ID despite validation evidence referring to that ID; identical target roots could undergo ABA generations. | Give candidate a typed kind-9 payload binding target/generation, exact computed source/revision/recipe/policy. Accept only under a target-local monotonic-generation CAS, versioned evidence, protected history policy and durable idempotent outbox receipt. Evidence remains separate and cannot hash back into its candidate. |

### Primary sources checked for the corrections

- [Git merge-base documentation](https://git-scm.com/docs/git-merge-base) explicitly admits several best ancestors in criss-cross histories; no single arbitrarily selected ancestor is sufficient. AVC's **virtual ancestry algorithm** is our own selected contract, not claimed to be inherited correctness from Git.
- [SQLite WAL](https://www.sqlite.org/wal.html), [synchronous=FULL](https://www.sqlite.org/pragma.html#pragma_synchronous), [SQLite's corruption caveats](https://www.sqlite.org/howtocorrupt.html) and the [online backup API](https://www.sqlite.org/backup.html) establish transactional/sync/snapshot boundaries, **not** external file + GC atomics. The tombstone barrier and backup root lease are derived from the counterexample, not a feature SQLite supplies automatically.
- [Linux fsync(2)](https://man7.org/linux/man-pages/man2/fsync.2.html) explicitly distinguishes flushing a file from persisting its enclosing directory entry. Platform-specific equivalents must be qualified; successful `rename` does not by itself guarantee a power-loss-durable object name.
- [BLAKE3's public specification](https://github.com/BLAKE3-team/BLAKE3-specs/blob/master/blake3.tex) supports a portable 256-bit digest and domain separation; AVC's particular envelope/kind registry and object codec are AVC contracts still requiring independent vectors.
- [Git merge behavior](https://git-scm.com/docs/git-merge) documents source-state/revert surprises in a standard three-way merge. This motivates AVC's explicit distinction between *revert as inverse source application* and impossible generic causal undo, not an unsupported promise to solve that problem.
- [Git's directory-rename-detection notes](https://git-scm.com/docs/directory-rename-detection) document conflicting file additions after directory renames and restrict automatic inference under collisions. AVC takes the narrower deterministic approach: only author-recorded moves guide base-descendant remapping; new old-prefix additions require an explicit recipe.

**Assessment:** State/Revision/ChangeId separation and a deterministic content-root remain coherent. The audit substantially tightens decoder semantics, merge limits, recovery, pinning and publication, but leaves **algorithm verification and physical implementation evidence** to qualification. No speed or universal superiority claim follows. The oldest Git-wrapper Rust code and original semantic oracle do not exercise these new normative contracts.


### Narrow independent specification probes (not format qualification)

A disposable, independent Python *shape* probe using synthetic file Entries and **SHA-256 surrogates instead of AVC BLAKE3** reconstructed sorted radix-name sets across leaf/branch and odd-nibble child contexts; 60 key-insertion permutations per test case produced identical synthetic node bytes. For one synthetic six-byte-name workload, the leaf/branch transition occurred at 96 keys (95-entry MapLeaf: 4089 payload bytes); this is an illustration of the 4096-byte inequality, **not** a throughput measurement or universal fanout count. It caught and corrected a mistaken empty-leaf illustration: the canonical `MapLeafPayload` for zero entries is **`00000000`**, not `04000000`. Small LCS cases also distinguished repeated-line ambiguity from uniquely anchored disjoint edits. A two-operation logical pin-versus-GC-deletion state check confirmed the need for transactional exclusion, **not** any physical crash behavior.

These scratch probes are not stored as AVC native implementation, have no BLAKE3 hashes, and are **not** a second independent production parser. Canonical byte/hash vectors and real fault/concurrency verification remain Milestone-0 work.


## 8. Executable canonical-format qualification — October 16, 2026

**Result: partial Milestone-0 qualification, not a format freeze.** Added a small, no-external-dependencies [BLAKE3 reference](experiments/blake3_reference.py), [object fixture builder](experiments/codec_reference.py), an **independently structured strict decoder and flat-key radix re-encoder** ([checker](experiments/codec_verify.py)), [pinned object vectors](experiments/codec_vectors.json), and [adversarial regression tests](experiments/test_codec.py). Execute `python -m unittest discover -s docs/experiments -p 'test_codec.py' -v`. These are specification tools, explicitly not a native object-store implementation or secure production parser.

The BLAKE3 fixture implementation matched **11 official unkeyed 256-bit hash vectors** spanning empty input, 64-byte blocks and 1024-byte chunk boundaries, plus the known `abc` digest. Against that implementation, the builder and independently written decoder/alternate radix constructor agreed on **27 pinned object examples** drawn from all nine proposed kinds, constructing 110 distinct typed objects. The initial thirteen named Python tests passed (local Python 3.13, October 16, 2026), including 4095/4096/4097-byte map thresholds, odd-nibble context, prefix-ending names, subtree ID reuse, metadata-dependent Revision IDs, inline/grouped conflicts, and bad-hash/bad-encoding/missing-closure rejection. Randomized insertion-order permutations of representative maps yielded the same roots. SHA-256 digests in the vector JSON are merely independent fixture-payload cross-checks for large representations; **AVC object IDs remain BLAKE3**.

**Observed nuance:** `CoupledSubtree` is allowed an absent alternative **below** the State root (deleted directory); a conflicted State root itself must have only present directory-valued alternatives. The fixtures encode and reject the contrasting cases. Also, an underfilled branch with complete, hash-valid children is noncanonical even if every referenced hash verifies. These findings tighten the spec but do not change the selected source authority, radix partition or format constants.

Primary reference: [BLAKE3-team test vectors](https://github.com/BLAKE3-team/BLAKE3/tree/master/test_vectors) and [Rust reference implementation](https://github.com/BLAKE3-team/BLAKE3/blob/master/reference_impl/reference_impl.rs). The tiny Python hash implementation is **unoptimized and not security-reviewed**. It is independently cross-checked against known answers. Subsequent cross-language work below now removes the single-runtime limitation, but no Rust codec, comprehensive input fuzzing, verified crash ordering, native GC, real multi-parent source merge, or performance proof exists. Those remain [qualification gates](roadmap.md).

### Independent second-language verification and a nested-conflict counterexample

The [Node.js codec cross-check](experiments/codec_crosscheck.mjs) separately implements unkeyed BLAKE3-256, all nine v0 object payloads, deterministic radix construction and strict decoding without importing the Python codec or hash function. It independently matches **27 pinned full object IDs**, exact small payload bytes and large-payload SHA-256 checksums for **110 typed fixture objects**. The second BLAKE3 implementation independently matches published block/chunk boundary known answers. Both languages agree on **32 seeded map constructions** (16 cardinalities from empty to 400, varied raw byte names and insertion orders). The Python suite now has **17 passing tests**, including **200 hash-valid one-byte mutated payloads** exercised for safe decoder failure. These are useful finite checks, not exhaustive security fuzzing.

**Actual reference-decoder bug:** A State-root CoupledSubtree could contain a *present nested* CoupledSubtree with a deletion alternative and still be accepted as directory-valued. The earlier validator only tested the nested region byte, instead of proving its alternatives were recursively present directories. Both reference validators now recursively check present directory-valued terms through inline and grouped alternatives; a non-root CoupledSubtree still permits a **direct** absent alternative. A nested possibly-deleted conflict is not a present directory-valued Entry and cannot be used to evade the root invariant. Existing 27 pinned object IDs and the selected byte constants remain unchanged.

**Limits:** The second implementation is JavaScript, **not a native Rust engine**. Cross-language agreement on known vectors, seeded maps and small negative suites does not establish general parser completeness, admissibility of arbitrary graphs, resilience under hostile fuzz campaigns, production performance or failure-domain durability. Native-language differential checking, further merge/source-model qualification and transaction/concurrency model checking remain next.

### Bounded root/GC/publication state machine — October 16, 2026

This paragraph records the then-proposed hybrid-store model; section 11 replaces its external-file crash-cut probe and updates the model to atomic SQL deletion. The old state counts below are historical, not current qualification totals.

The [authority state model](experiments/authority_model.py) uses pure Python exhaustive interleaving enumeration for a **single immutable object**, one root-admitting writer, a reader, a root-set backup lease and a collector. With a stale mark followed by an unchecked sweep, the model reaches **19 unsafe states among 107 distinct states** from an initially unrooted object. The shortest counterexample is `scan → writer-pin → sweep-old-mark`; another executes `scan → writer-pin → writer-commit-root → sweep-old-mark` and destroys **acknowledged** source. With the specified transactional `Deleting` tombstone and pin/admission exclusion, all **123 reachable states from unrooted** and **81 from rooted** satisfy the modeled root/pin custody invariant. A separate exact-target CAS model checks two competing proposals, persisted retry receipts, conflicting idempotency keys, a single outbox event per acceptance and the root `A→B→A` ABA case; a selected crash-cut example shows why committing a root before directory sync is unsafe.

**Model limits:** It assumes each state action is linearizable and single-host filesystem sync/rename has the stated persistence semantics; it does **not** implement SQLite, real files, GC over multi-object graph closure, concurrent compaction, actual backups, authorization or remote systems. Hence zero violations in the bounded model is **not** production durability or full publication qualification. The older [GC contract probe](experiments/vcs_contract_probes.py) demonstrated loss with *missing initial staging pins*; this newer model specifically checks the subtler **re-pin after stale marking** race. Keep both because they catch distinct failure modes.


## 9. LayerFS — transferable ideas and limits (October 19, 2026)

**Scope:** Reviewed [LayerFS](https://github.com/Ephemeral-AI-Lab/layerfs) `main` at `8a8981d73fc7ff852c6cdfb22db2dee83136464c`, its Rust source, current product/storage/workspace/merge documents, and its dated [#334 evidence](https://github.com/Ephemeral-AI-Lab/layerfs/blob/8a8981d73fc7ff852c6cdfb22db2dee83136464c/core/docs/issues/334/RESULTS.md) and [#352 storage studies](https://github.com/Ephemeral-AI-Lab/layerfs/blob/8a8981d73fc7ff852c6cdfb22db2dee83136464c/core/docs/issues/352/STORAGE_STUDY.md). The README advertises v0.1.7 and an **unreleased** 1.0 planned for October 21. Older measurements and docs pinned to development branches are historical evidence, not assertions about a stable release. This assessment is **static research**, not an AVC-vs-LayerFS benchmark.

**Inode indirection is a trade-off, not a free path-tree improvement.** The [actual filesystem root](https://github.com/Ephemeral-AI-Lab/layerfs/blob/8a8981d73fc7ff852c6cdfb22db2dee83136464c/core/crates/layerfs-content/src/filesystem/root.rs) hashes a profile, allocation scope, root inode serial and inode table. [Directory bindings](https://github.com/Ephemeral-AI-Lab/layerfs/blob/8a8981d73fc7ff852c6cdfb22db2dee83136464c/core/crates/layerfs-content/src/filesystem/directory/update.rs) map names to serials; [inode records](https://github.com/Ephemeral-AI-Lab/layerfs/blob/8a8981d73fc7ff852c6cdfb22db2dee83136464c/core/crates/layerfs-content/src/filesystem/inode/update.rs) map serials to values. A file-content edit can update an inode-table path without rewriting every ancestor directory; linked names and recorded moves can share identity. Conversely, otherwise equivalent source namespaces with different allocation scopes or serial histories need not share a root hash. AVC **requires** equal typed namespaces to have the same StateId independently of edit history, and does not canonically preserve hard-link identity in v0. Putting persistent allocation serials into AVC's State would violate that invariant absent a new canonical normalization algorithm. **Decision:** retain the selected path-Merkle namespace; workspace-local handles or derived indexes can be separate. Measure read/write/diff and inode-index costs under identical source workloads later; never infer universal superiority from one benchmark.

**Managed workspaces improve observation, not automatically durability.** LayerFS's Linux [FUSE sessions](https://github.com/Ephemeral-AI-Lab/layerfs/blob/8a8981d73fc7ff852c6cdfb22db2dee83136464c/core/docs/architecture/76-native-mount-session.md), independent overlays, and kernel [cache invalidation after merge](https://github.com/Ephemeral-AI-Lab/layerfs/blob/8a8981d73fc7ff852c6cdfb22db2dee83136464c/core/docs/architecture/81-compare-and-merge.md) show a route to cheap no-copy workspace mounts and operation-level observation. A managed mount can record *actual operations* rather than deducing rename identity from equal bytes—but capture coverage still depends on page-cache/writeback, mapped writes, open handles and a real writer/snapshot boundary. LayerFS's [FUSE callback](https://github.com/Ephemeral-AI-Lab/layerfs/blob/8a8981d73fc7ff852c6cdfb22db2dee83136464c/core/crates/layerfs-fuse/src/request/callbacks.rs) explicitly returns `ENOSYS` for FSYNC/FSYNCDIR/FLUSH, and [documents that the kernel reports success](https://github.com/Ephemeral-AI-Lab/layerfs/blob/8a8981d73fc7ff852c6cdfb22db2dee83136464c/core/docs/architecture/76-native-mount-session.md) without syncing its disposable backing; [libfuse specifies the same ENOSYS-as-success behavior](https://libfuse.github.io/doxygen/structfuse__lowlevel__ops.html). This is **not** a valid protected-byte acknowledgement for AVC. **Decision:** keep ordinary directories and fresh-directory restore mandatory; a mounted COW backend is optional later and must qualify sync semantics, cache coherence, root switching, retention and crash outcomes independently of its user-visible convenience.

**Physical layout evidence supports optimization, not a new canonical format.** LayerFS uses [BLAKE3/CDC streaming with 8/16/32 KiB chunk bounds](https://github.com/Ephemeral-AI-Lab/layerfs/blob/8a8981d73fc7ff852c6cdfb22db2dee83136464c/core/crates/layerfs-content/src/file/cdc/gear.rs), bounded physical deltas and compressed pooled metadata. AVC already permits physical CDC and bounded deltas *beneath a whole-logical-BlobId*; sparse zero-run encoding could also be evaluated as a physical optimization. No canonical format changes are justified. The [#334 diagnostic run](https://github.com/Ephemeral-AI-Lab/layerfs/blob/8a8981d73fc7ff852c6cdfb22db2dee83136464c/core/docs/issues/334/RESULTS.md) reports **769,980,226 cumulative logical snapshot bytes / 6,348,800 SQLite-file bytes (~121×)**. Its **numerator** sums many full historical source states; the SQLite file is the denominator. This is **not** a controlled comparison with packed Git/Jujutsu or AVC under identical retention and durability. The [#352 study](https://github.com/Ephemeral-AI-Lab/layerfs/blob/8a8981d73fc7ff852c6cdfb22db2dee83136464c/core/docs/issues/352/STORAGE_STUDY.md) attributes roughly 31.7% of a measured store to metadata, 23.0% to indexes and 19.2% to waste at one pinned range; its [later physical inode-branch delta work](https://github.com/Ephemeral-AI-Lab/layerfs/blob/8a8981d73fc7ff852c6cdfb22db2dee83136464c/core/docs/issues/352/OPTIMIZATIONS.md) reports a **synthetic** 53k-inode, 100-write result of 2,894 → 338 encoded bytes per edited inode branch (not a whole-workflow benchmark). It reinforces bounding *fixed per-save/capture overhead* and checking read amplification and delta-chain caps. A timestamp-only difference in LayerFS may create an extra root; AVC's v0 State correctly excludes mtime.

**All-in-SQLite removes one class of cross-store ordering, not every custody problem.** LayerFS's current [global Store profile](https://github.com/Ephemeral-AI-Lab/layerfs/blob/8a8981d73fc7ff852c6cdfb22db2dee83136464c/core/docs/architecture/84-global-sqlite-store.md) is SQLite WAL with **`synchronous=OFF`**, intended for disposable local data, and admits no proven power-loss durability; real history GC also remains unimplemented there. SQLite documents that [WAL/FULL](https://www.sqlite.org/pragma.html#pragma_synchronous) must sync each committed transaction for its durability contract, unlike OFF. Keeping all objects in one SQLite transaction can simplify external-file staging and cross-store backup, but may increase WAL/checkpoint pressure, large BLOB/write amplification or lock contention at FULL. LayerFS's [single-writer contract](https://github.com/Ephemeral-AI-Lab/layerfs/blob/8a8981d73fc7ff852c6cdfb22db2dee83136464c/core/docs/architecture/83-store-concurrency-model.md) also records path-search growth inside its publication lane as a regression: minimize serialized work, but never silently re-merge a stale AVC candidate inside a transaction or weaken target-scoped CAS. **Decision at October 19 (superseded October 27):** retain the hybrid pending independent storage review. Section 11 now selects SQLite-only staged segments for a smaller initial trusted core, not on the strength of LayerFS's disposable-profile measurements; equal-durability performance and resource qualification remain.

**Do not import conflict policy or every-write authorship.** LayerFS's [merge rules](https://github.com/Ephemeral-AI-Lab/layerfs/blob/8a8981d73fc7ff852c6cdfb22db2dee83136464c/core/docs/architecture/81-compare-and-merge.md) sometimes take one side of binary/type collisions, use text markers and may resolve by mtime preference. That is a product choice, **not** lossless source uncertainty. AVC retains typed unresolved conflicts, separately recorded provenance, bounded conservative automatic merge and explicit resolution. LayerFS writes a Commit per SDK file mutation; its [per-Commit analysis](https://github.com/Ephemeral-AI-Lab/layerfs/blob/8a8981d73fc7ff852c6cdfb22db2dee83136464c/core/docs/architecture/85-commit-per-write-storage.md) shows why this imposes fixed metadata cost. AVC retains independent lightweight private captures and authored revisions.

**Outcome at October 19:** No foundational AVC architecture or Milestone-0 gate changes. Added a narrow optional managed-mount safety boundary in [design](design.md) and future fair-comparison/qualification rows in [roadmap](roadmap.md). No native engine, adapter or FUSE implementation was started.

This earlier pass corresponds to commit 58f103f; section 11 explicitly supersedes its width-group and opaque-recipe portions.

The native State/Revision/ChangeId model remains selected. Git conversion is a boundary adapter, not a Git-compatible backend; it must report unsupported/lossy cases rather than promise arbitrary native-history round trips. Format/layout candidates now require representative cost evidence **before** freezing user-data IDs, rather than deferring all evaluation to Milestone 5. No native engine was started and no comparative performance was measured.

| Recipe payloads larger than 1 MiB were accepted; deep valid histories could exhaust the host stack rather than return a bounded refusal. | Check recipe lengths before slicing. The disposable parsers explicitly cap 256 simultaneously open objects and 30,000 reference visits; budget refusal is not a claim that the canonical history is invalid. Native verifiers must qualify their own complete/streaming traversal. |
| A 20,010-byte, 2,001-line file with unique first/last edits exceeded 4M dense LCS cells. | Exact sparse LCS counts longest increasing match-pair chains and saturates ambiguity at two. ## 11. From-scratch simplification review — October 27, 2026

**Decision:** preserve native State/Revision/ChangeId semantics and Git conversion at the boundary, but reduce the initial trusted core. DeepSeek independently challenged storage custody and the typed-record boundary; MiMo challenged binary-conflict sufficiency and hosted scope. These are bounded design reviews, not correctness proofs.

- **SQLite-only local custody:** one transactional authority for payloads and roots removes the default external-file install/unlink and cross-store backup protocol. Large logical objects still need bounded segment rows and earlier unacknowledged stage commits; the final root/receipt commit is short. SQL-only logical retirement and current-pin checks remain necessary, including bounded cleanup for large objects. A conservative protection-generation barrier keeps full tracing outside short writer transactions; churn can restart/starve collection, not invalidate other workspace requests. This choice minimizes new trusted code; it does **not** claim faster FULL-durable writes, less WAL traffic or cheaper backups.
- **Binary conflicts:** all current merge producers are pairwise and N-way composition is explicitly ordered. No required workflow needs arbitrary direct width. Nested opaque nodes retain original alternatives, at the explicit cost of grouping-sensitive identity and earlier depth-limit refusal on long folds. Never cancel an inner term. Remove kind-8 grouping rather than keep an unused alternate representation.
- **Closed typed provenance:** Transform stores exact base, checked structural operations and ordered conditional leaf edits; Merge fixes inputs/algorithms; Observation records source-admission scope and explicit partial/resolution choices. Construction and observation can coexist without making either source authority. Completed-scope coverage avoids a per-path metadata explosion for successful wide scans without claiming an atomic snapshot. No opaque executable byte string, plugin registry or persisted virtual-merge graph is needed: the deterministic trace is derived. Replaying for evidence must reproduce the bound State; decoding alone proves neither the claim nor authorization.
- **Local first, hosted later:** seven local object kinds; retire experimental tags 8/9 without reuse. Candidate identity/evidence framing belongs to the hosted protocol's own pre-ship gate. Keep local root CAS/receipts/outbox, native verified export and the whole-closure durable draft receipt before ephemeral worker destruction.
- **Keep packed radix provisionally:** the simpler-looking one-key-leaf alternative loses much of the candidate's small-directory packing. The finite comparison below shows no unqualified winner; it does not justify silently changing the source-ID structure.

### SQLite evidence and remaining limits

Primary documentation rechecked October 27: [row/BLOB limits](https://www.sqlite.org/limits.html), [WAL](https://www.sqlite.org/wal.html), [FULL versus NORMAL](https://www.sqlite.org/pragma.html#pragma_synchronous), [online backup](https://www.sqlite.org/backup.html) and its [exact API/restart rules](https://www.sqlite.org/c3ref/backup_finish.html), and [vacuum/free-space behavior](https://www.sqlite.org/lang_vacuum.html). SQLite can commit bounded segments before publishing a protected root. A completed backup contains payload and metadata together; read its manifest from that image because concurrent writes can restart incremental copying. Multi-transaction native exports still need exact-root leases. Long readers can impede checkpointing; deleted pages need not shrink the file. The historical large-WAL-transaction warning was fixed in SQLite 3.11, not a current 100-MB limit.

The [real SQLite probes](experiments/test_sqlite_custody.py), run with local SQLite **3.53.1**, deliberately lower the row limit to 8,192 bytes, reject one 25,600-byte value, then stage it in 1,024-byte segment rows. They check no root is acknowledged by those stage commits, transaction interruption rolls back root/receipt/outbox together, current reader pins defeat a stale GC candidate, late pins cannot resurrect deleted objects, and a completed backup reconstructs the source after removing the live DB. This is a **single-object toy schema**, not AVC storage, multi-object closure validation, process-crash testing or proof of power-loss survival. Large-file streaming, WAL/checkpoint/disk-full resource behavior and qualified platform sync remain hard gates.

The group-width and core-candidate fixture families are removed because their schemas no longer exist; binary depth, root-deletion and source-preservation protection remains. The hypothetical external-file fsync ordering test is replaced by real SQLite boundary probes, while the model still checks stale marks/current pins and CAS/receipt ABA. Conflict/provenance and dependent fixture IDs are intentionally regenerated **before release**; clean-source, hash framing and map IDs are unchanged. No native engine, Git adapter, deployment or package-version change is included.

## 12. User workflows and private history boundaries — October 27, 2026

The storage design did not settle the everyday experience. Git's [reset reference](https://git-scm.com/docs/git-reset) documents different history/index/file effects under one command; its [worktrees](https://git-scm.com/docs/git-worktree) already support independent directories. [Jujutsu's comparison](https://docs.jj-vcs.dev/latest/git-comparison/) provides a stronger UX baseline: working-copy commits, direct change splitting, conflict persistence and operation undo. These are documented capabilities, not a survey of user complaints or evidence AVC is easier.

The selected [workflow contract](ux.md) preserves deliberate file/hunk selection without requiring a mutable staging index. It makes new-file inclusion explicit, binds previews to immutable checkpoint values, keeps status read-only, and distinguishes history undo from file recovery. It rejects automatically capturing on inspection, blindly carrying dirty work across a switch, guessing a rewritten change by timestamp, and displaying coupled source conflicts as independent file choices. Those shortcuts reduce apparent ceremony by concealing effects or inventing intent.

Independent MiMo review exposed onboarding, deletion/coverage, candidate custody, expired leftovers, reference resolution and coupled-resolution risks. The chosen fixes use concrete disclosures and existing capture/receipt contracts. We did **not** extend all excluded work to permanent commit retention, invent causal hunk identities, choose an arbitrary bulk-deletion count or automatically reapply dirty edits during switching. Private checkpoint retention remains explicit and bounded; the flow must not call uncaptured bytes safe.

**A real ownership defect:** C contained private data; an amended C' retained C's parents but mandatory observation provenance still owned C/base/expected values. Exporting C' therefore exported discarded private bytes absent from its authored parent history. DeepSeek independently confirmed the trace. A source-ID-preserving snapshot VCS does not need a permanent replay-input chain to reconstruct C'.

**Repair:** Provenance owns only its bound result State. Binding byte 1 marks all other typed input/Entry/evidence IDs as non-owning commitments. Decoding checks their shape, never fetches them and never treats them as trusted proof. Explicit replay/move verification must protect authorized input roots separately; optional continued audit custody gets its own private pin/receipt/deadline. No new canonical evidence-bundle kind, second provenance schema or push-time metadata rewrite is needed. Actual Revision parents still own history. Public paths/fingerprints can disclose information or permit low-entropy guesses; this is not secret erasure or metadata anonymity. Private capture receipt IDs stay out of canonical authoring metadata by default.

The focused codec regression removes the discarded predecessor/state/map/blob from the available store and validates C' in Python and Node. It failed with the old owning-audit behavior. Explicitly adding the old revision as an audit root still retains its bytes; source-only closure does not. Present or corrupt private audit targets cannot affect source admission either. Existing evidence-content mismatch assertions are now evidence-layer gates, not canonical-shape predicates: a claim's truth cannot depend on whether private objects happen to be present in a reader's store. Native evidence replay remains unimplemented and separately qualified. The unreleased Provenance binding byte and dependent vectors are deliberately repinned; source/map/conflict IDs are unchanged.

First-run paper qualification also found that Selection could name only a Revision. It now explicitly permits a StateOnly base: init uses the canonical empty State without authoring fake history, while nonempty state-only recovery requires an explicit history-parent/root choice. Capture-to-amend preserves the amended ChangeId/parents instead of reusing normal promotion's new-change semantics.

These are design/reference corrections, **not** usability results. Real user task trials, command implementation, replay checks, repeated-line merge burden and crash/platform behavior remain open gates. No legacy Rust CLI or native engine was implemented.

## 13. Harmless alignment ambiguity — October 27, 2026

**Finding:** requiring a unique optimal line alignment confused ambiguous positions with ambiguous source output. Removing one of two identical blank lines has several optimal match sequences, but a distant independent edit can have the same clean result under every sequence. The unique-only candidate interrupted that workflow unnecessarily. This refines that earlier policy, not the lossless-conflict invariant.

The [reproducible study](experiments/text_merge_study.py) reads four source files at pinned revision `19710524aa87cdd076bd8755257fa17b71bb7a69`, without executing their contents. It applies declared disjoint line edits and derives expected bytes directly from those edits. Four ordinary replacement pairs merge under the preceding policy; four blank-line insertion/deletion pairs conflict. The refined candidate, **Git 2.56.0** (`merge-file`, default algorithm) and **Jujutsu 0.46.0** (actual two-parent changes) all produce the intended bytes in **eight of eight** cases. Git/Jujutsu run in fresh temporary directories with isolated user configuration. [Recorded results](experiments/text_merge_results.json) retain input/expected hashes, source revision, driver hash and tool versions.

**Selected correction:** keep the sparse unique-alignment fast path. For ambiguous inputs, enumerate every optimal alignment within explicit content-derived cell/work/variant budgets. Accept only if every left/right pairing is non-overlapping under the existing hunk rules and produces identical bytes. One conflicting pair, differing output or exhausted deterministic budget still means conflict. Do not greedily trim context, choose the first alignment, retry with a heuristic, or convert allocation/cancellation failures into source values. The authoritative rule and exact limits live in design.md.

The [reference](experiments/text_merge_reference.py) compares complete alignment sets with the independent recursive oracle for **961 pairs**, and merge outcomes with independent subset-enumeration/application for **3,375 three-way cases**. Boundary tests retain conflicts where any plausible pairing overlaps, while accepting the formerly rejected identical-output deletion. Budget cases cover matrix size, enumeration work, 64/65 variants, cross-product size and rendered-byte work; the 2,001-line unique case still avoids the dense fallback. Object framing, codec vectors, package version and the legacy CLI are unchanged.

**Limits:** these are controlled synthetic edits on real files, not sampled real merge histories, user testing, a semantic-correctness proof or a speed comparison. The study deliberately targets one known failure; its counts are not a general conflict rate. The fallback adds bounded quadratic work on ambiguous small files and still refuses difficult/large cases. Real-history false-clean/conflict review burden and native resource qualification remain open before driver freeze. This revises the unreleased candidate; published driver behavior must be versioned rather than silently changed.
